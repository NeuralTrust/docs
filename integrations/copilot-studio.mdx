Microsoft Copilot Studio is a low-code Power Platform service used to build
conversational agents. Makers define instructions, add knowledge sources and
tools, and publish agents to Teams, websites, or Microsoft 365.

Microsoft hosts model execution, so nothing of ours sits in the data path. There
are two integration points, and they solve different problems. Use one or both.

## Choose a path

| Path | What it does | What you can enforce | Where you configure it |
|---|---|---|---|
| **[Threat detection](/integrations/copilot-studio-threat-detection)** | Copilot Studio calls TrustGuard **before every tool the agent is about to run**, including what earlier tools returned — whatever built that tool. | Monitor · Block | Power Platform admin center, per environment |
| **[Governed tool access](/integrations/copilot-studio-governed-tool-access)** | TrustGate publishes the assigned MCP servers through one OAuth endpoint and limits the catalog to the consumer's registries and toolkit. | Tool access and rate limits | The agent's MCP tool connection |
| **Governed tool access + TrustGuard** *(optional)* | The same MCP path, with a policy that evaluates `tools/call` requests and `CallToolResult` responses. | Monitor · Block · Transform | On the TrustGate consumer |

The two paths are independent. Threat detection screens every tool the agent
runs, whatever its source. Governed tool access governs only the MCP tools
TrustGate publishes.

These integrations apply to Copilot Studio agents that use **generative
orchestration**. They do not apply to Microsoft 365 Copilot in Word, Teams, or
Outlook.
