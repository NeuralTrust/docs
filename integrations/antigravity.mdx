Google Antigravity is the coding agent that succeeds Gemini CLI. The IDE, the
CLI, and `agy` can read repositories, edit files, run shell commands, and call
tools on a developer's machine.

TrustGuard lifecycle hooks evaluate those local actions. The hooks ship in the
[trustguard-gemini-cli-plugin](https://github.com/NeuralTrust/trustguard-gemini-cli-plugin)
repository, the same package Gemini CLI uses.

## NeuralTrust controls

| Product | Scope | Controls |
| --- | --- | --- |
| **[TrustGuard](/trustguard/overview)** | Evaluates the prompt, the tool call, and the model reply against an organization [policy](/trustguard/concepts/policies). | Block · force-ask on `PreToolUse`. A blocked prompt is injected back to the model |

`PreToolUse` is the only event that can stop a tool. A policy ask becomes
`force_ask`, so Antigravity's "Always Allow" cannot skip it. TrustGuard does
not answer `allow` on `PreToolUse`: that would auto-approve the tool and skip
the developer's own review settings.

Prompt blocking is soft. With `prompt_enforcement` set to `inject` (the
default), a blocked prompt is shown to the model before it answers.
`inject_terminate` also ends the turn when the reply is blocked. `off` only
records the event. The hard guarantee remains `PreToolUse`: if the model
ignores the message and calls a tool, that call is still evaluated.

## Before you start

| Requirement | Notes |
|---|---|
| Egress from developer machines to `{TRUSTGUARD_BASE_URL}` | The console shows the [base URL](/trustguard/api/evaluate#base-url) for your workspace. |
| The **Google Antigravity** collector | **Agent Runtime → Collectors → Catalog → AI assistants & coding agents → Google Antigravity**. Create the `tgk_…` key on its **Auth** tab and assign the policy on the **Policies** tab. |
| Node.js | Antigravity and the hook bootstrap both need it. |
| Egress to GitHub Releases | On first use the bootstrap downloads the checksum-pinned `trustguard-gemini-cli` binary. |

<Note>
Create the policy in **Observe** mode. Observe records decisions in **Activity**
without enforcing them. Review the results, then switch the policy to
**Enforce**. See [Policies](/trustguard/concepts/policies).
</Note>

Developers do **not** need NeuralTrust accounts.

## Install the hooks

```bash
git clone https://github.com/NeuralTrust/trustguard-gemini-cli-plugin.git
cd trustguard-gemini-cli-plugin
python3 scripts/install-antigravity-hooks.py --user
```

That merges a `trustguard` entry into `~/.gemini/config/hooks.json` and leaves
every other hook in place. It also downloads the pinned binary when one is not
already installed, then checks that `PreToolUse` returns `deny` when TrustGuard
cannot be reached. If that check fails, the install stops. A binary from the
`v0.1.0` release answers `{}` and never calls TrustGuard, so this check is how
you tell an outdated binary from a working one.

`make build` only writes `./bin/trustguard-gemini-cli`. The hooks do not look
there. To try a local build, copy it where the bootstrap looks first. That
copy takes priority over the downloaded release:

```bash
make build
cp bin/trustguard-gemini-cli ~/.trustguard/bin/trustguard-gemini-cli
python3 scripts/install-antigravity-hooks.py --user
```

Antigravity reads `hooks.json` at startup. Restart the IDE or CLI, then run
`/hooks` in the CLI to confirm the commands.

The user file is the default because some CLI versions ignore the workspace
file `.agents/hooks.json`. To install it anyway:

```bash
python3 scripts/install-antigravity-hooks.py --workspace /path/to/project
```

macOS and Linux call `trustguard/hooks/trustguard-hook.sh`. Windows calls
`trustguard-hook.ps1`. Both forward the event name to `trustguard-gemini-cli`.

## Deploy the managed config

Antigravity and Gemini CLI share one config file. Deploy it with MDM:

```json
{
  "data_url": "https://<your-trustguard-host>",
  "api_key": "tgk_…",
  "fail_mode": "open",
  "prompt_enforcement": "inject"
}
```

`prompt_enforcement` is `inject`, `inject_terminate`, or `off`. `inject` is the
default. Observe mode records the decision and does not inject or terminate.

| OS | Managed config path |
| --- | --- |
| macOS | `/Library/Application Support/TrustGuard/gemini-cli.json` |
| Linux | `/etc/trustguard/gemini-cli.json` |
| Windows | `%ProgramData%\TrustGuard\gemini-cli.json` |

For a pilot without MDM, write the same JSON to `~/.trustguard/gemini-cli.json`
and `chmod 600` it.

`fail_mode: "open"` allows the tool when TrustGuard cannot be reached.
`fail_mode: "closed"` denies `PreToolUse` in that case and still lets the
telemetry events through, so a network blip does not freeze the agent.

## What is evaluated

| Antigravity event | Sent to TrustGuard | Effect on the agent |
| --- | --- | --- |
| `PreToolUse` on `run_command` | The shell command (`CommandLine`) | `deny`, `force_ask`, or `overwrite` when a transform returns replacement text. A clean allow leaves the decision empty |
| `PreToolUse` on other tools | The tool name and arguments | Same |
| `PostToolUse` | The tool result or error | None |
| `PreInvocation` | The user prompt from the session transcript | `injectSteps` when the prompt is blocked and enforcement is on |
| `PostInvocation` | The model reply from the session transcript | `terminate` only with `prompt_enforcement: inject_terminate` |
| `Stop` | Why the run ended | None |

Activity shows these calls with `source.application` = `antigravity-plugin`.

## Verify

1. The installer prints `smoke ok` and a path to `trustguard-gemini-cli`. If it exits because `PreToolUse` did not return `deny`, the installed binary is older than the Antigravity support. Copy a current build into `~/.trustguard/bin` and run the installer again.
2. Run a shell command Antigravity would execute, such as listing a directory.
3. In **Activity**, confirm an event with `source.application` = `antigravity-plugin`. A prompt event should contain the text you typed, not a line that only names the model.
4. Put the policy in **Enforce** and add a rule that blocks that command. The next `PreToolUse` should return `deny` and Antigravity should not run it. A rule that asks should return `force_ask`, including after "Always Allow".
