---
title: "Semantic Cache"
description: "Answer a request from an earlier response instead of calling the model, when the two are identical or close enough. Cheaper and faster, and only right for prompts whose answer does not depend on who is asking."
---

Applies to **LLM**.

The cache keeps responses the gateway has already returned and serves one again
when a new request matches. A hit costs an embedding lookup instead of a model
call, and returns in the time the lookup takes.

## What counts as a match

| Mode | Matches when |
|---|---|
| **Exact** | The normalised request text is identical. |
| **Semantic** (default) | The request's embedding is within the **similarity threshold** of a cached one. The default of 0.85 is a reasonable start; raise it when a hit comes back for a question that was only similar, lower it when nothing ever hits. |
| **Both** | Exact first, then semantic. |

Semantic matching needs an **embedding provider**, an **embedding model** and a
credential for that provider. Every lookup is an embedding call, so the cache
trades one small model call for a possibly large one.

## Whose answers are shared

**Scope** decides who can receive a cached response. **Per application** (default)
keeps each application's cache to itself. **Gateway-wide** shares one cache across
every application on the gateway, which is a real saving for a shared FAQ-style
workload and a data-exposure problem for anything else: an answer cached from one
application's conversation would be served into another's.

A cached answer is also blind to who asked. A prompt whose right answer depends
on the caller — their account, their permissions, today's date — should not be
cached at all, which is what the **Requests from** scope is for.

## What is never cached

By default a response is stored only when the model answered with status 200, and
requests that carry tool definitions, or responses that contain tool calls, are
skipped — a tool call is an action, not an answer to replay. Streaming requests
can be skipped as well.

A client can step around the cache for one request by sending the **bypass
header**, `X-Cache-Bypass` by default: no lookup, no store.

Entries expire after the **TTL**, 24 hours unless you change it. The **vector
store** is where entries live: **Redis** (default), **pgvector**, or **in
memory**, which is per gateway instance and lost on restart, so it is for trying
the policy rather than running it.
