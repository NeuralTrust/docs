The **CORS** policy (`cors`) sets Cross-Origin Resource Sharing headers for browser apps that
call the gateway proxy. Create it under **Policies** → **Catalog** (or **New policy**) and
scope it **gateway-wide** or to specific [consumers](/trustgate/concepts/consumers).

## Configure in the console

1. Open **Policies** → **Catalog** (or **New policy**).
2. Choose **CORS**.
3. Set **Scope**: **Enforce** / **Observe** as needed; **Gateway-wide** or **Targeted**
   consumers.
4. Fill origins, methods, headers, credentials, and Max-Age.
5. Optionally log violations.
6. Save.

## Typical settings

| Setting | Meaning |
|---|---|
| **Allowed origins** | Exact origins or patterns browsers may use. |
| **Allowed methods** | e.g. `GET`, `POST`, `OPTIONS`. |
| **Allowed headers** | Request headers the browser may send (include your API key header if needed). |
| **Expose headers** | Response headers JS may read. |
| **Allow credentials** | Cookies / auth headers on cross-origin calls. |
| **Max-Age** | Preflight cache duration. |

Server-level CORS middleware env vars (self-host) are separate — see
[Configuration](/trustgate/operate/configuration). Prefer the **policy** for per-gateway
product control.
