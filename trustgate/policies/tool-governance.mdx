---
title: "Tool governance"
description: "Govern agent tool use at the gateway: inject operator-authored tools and rate-limit individual tool calls observed in model responses."
---

For agent and function-calling traffic, TrustGate can govern the **tools** in flight with two
catalog policies. Both are configured like any other [policy](/trustgate/policies/overview)
and scoped global or per consumer.

| Policy (`slug`) | Stage | Acts on |
|---|---|---|
| [`tool_injection`](#tool-injection) | `pre_request` | The request `tools[]` array |
| [`per_tool_rate_limiter`](#per-tool-rate-limiter) | `pre_request` · `pre_response` · `post_response` | Observed tool calls |

---

## Tool injection

The **`tool_injection`** policy appends operator-authored function tools to the request
before they reach the model — a governance and steering layer, **not** an access gate. Name
collisions with tools already on the request are resolved by `on_conflict`.

| Setting | Type | Default | Notes |
|---|---|---|---|
| `inject_tools` | array | — | Operator-authored function tools appended to the request. **Required.** |
| `inject_tools[].type` | enum | `function` | Only `function` tools are supported. |
| `inject_tools[].function` | object | — | `{ name, description, parameters }` — `name` required; `parameters` is a free-form JSON schema. |
| `on_conflict` | enum | `gateway_wins` | Name collision resolution: `gateway_wins`, `client_wins`, or `reject`. |

```json
{
  "slug": "tool_injection",
  "settings": {
    "inject_tools": [
      {
        "type": "function",
        "function": {
          "name": "search_kb",
          "description": "Search the internal knowledge base.",
          "parameters": {
            "type": "object",
            "properties": { "query": { "type": "string" } },
            "required": ["query"]
          }
        }
      }
    ],
    "on_conflict": "gateway_wins"
  }
}
```

## Per-tool rate limiter

The **`per_tool_rate_limiter`** policy counts and enforces limits **per observed tool call** in
model responses. The limit applies gateway-wide when the policy is global, otherwise per
consumer. (In the Admin Console catalog it is listed under Traffic Control.)

| Setting | Type | Default | Notes |
|---|---|---|---|
| `rules` | array | — | Ordered `[{ tool, windows, behavior }]`; the first matching `tool` glob wins. **Required.** |
| `rules[].windows` | array | — | `[{ duration, max }]` fixed windows for the matched tool. |
| `behavior_default` | enum | `reject_response` | Applied to rules without an explicit behavior. |

Per-rule / default `behavior` is one of `reject_response`, `inject_error_result`, or
`strip_tool_from_request`.

```json
{
  "slug": "per_tool_rate_limiter",
  "settings": {
    "rules": [
      { "tool": "execute_code*", "windows": [{ "duration": "1m", "max": 5 }] }
    ],
    "behavior_default": "inject_error_result"
  }
}
```
