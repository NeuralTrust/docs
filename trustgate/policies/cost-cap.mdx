title: "Cost cap"
description: "Per-request USD ceilings on model list price — configure the cost cap policy in the console to reject or downgrade expensive calls."
---

The **cost cap** policy (`cost_cap`, labeled **LLM Cost Cap** in the catalog) guards a single
request against model list price (USD per 1k tokens). It is **stateless per request** — for
running token/dollar **budgets over time**, use
[LLM Budget](/trustgate/policies/rate-limiting) (`token_rate_limiter`) instead.

## Configure in the console

1. Open **Policies** → **Catalog** → **LLM Cost Cap** (or search `cost_cap`).
2. Set **Scope**: mode (**Enforce** / **Observe** / **Throttle** where offered),
   **Gateway-wide** or **Targeted** consumers.
3. Configure the default ceiling and optional **per-model overrides**.
4. Choose behavior when exceeded: **reject** or **downgrade** to a cheaper model.
5. Save. Attach from the consumer **Policies** tab if targeted.

## What you control

| Control | Meaning |
|---|---|
| **Default cap** | Max estimated USD for a request under the default pricing table. |
| **Per-model overrides** | Tighter or looser caps for specific model ids/patterns. |
| **Custom pricing** | Optional rates when the built-in table is wrong for your contract. |
| **On exceed** | Reject the call, or rewrite to a **downgrade** model (same provider family). |

## When to use cost cap vs LLM Budget

| Policy | Best for |
|---|---|
| **Cost cap** | Block one oversized prompt/completion immediately. |
| **LLM Budget** | Daily/monthly token or dollar pools; throttle or downgrade over a window. |
