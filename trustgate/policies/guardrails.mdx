title: "Guardrails"
description: "Inspect what goes in and what comes out. TrustGuard, a provider's moderation service, an AWS guardrail, or deterministic regex — and the one thing none of them can do."
---

Applies to **LLM and MCP**. Each guardrail inspects the request, the response, or
both, and blocks or transforms what matches.

## The one limit shared by all of them

**Streaming responses cannot be inspected or blocked in real time.** Tokens are
already leaving when a detector would decide. Put guardrails on the request leg,
or on non-streaming responses, for enforcement. A response guardrail on a
streaming application observes; it does not protect.

## TrustGuard

Runs [TrustGuard](/trustguard/overview) detectors — jailbreak, PII, secrets,
toxicity, tool abuse, multi-turn attacks — against the request, the response, or
both, and applies the action TrustGuard returns. It needs an Agent Runtime
collector connected to this gateway; the policy creates one if none exists.

**On error**: fail open (default) or fail closed for transport and service
failures. Authentication, rate-limit and entitlement responses from TrustGuard
always block regardless — a gateway that cannot prove it is allowed to call the
detector does not get to guess.

Findings correlate with [Telemetry alerts](/platform/alerts), which is the
argument for this one over a provider's moderation API when you already run
TrustGuard.

## OpenAI Moderation

Screens text with OpenAI's moderation model against per-category thresholds; a
score at or above a threshold blocks, and **block on flagged** blocks anything
OpenAI flags even without a threshold. Needs an OpenAI key of its own. Text only.

In enforce mode it **fails closed** on any moderator error.

## Azure Content Safety

Azure's Analyze Text against **Hate**, **Violence**, **SelfHarm** and **Sexual**,
with a severity threshold per category; only the categories you list are
enforced. Needs the endpoint and a subscription key. Request leg only. Fails
closed in enforce mode.

## AWS Bedrock guardrail

Reuses a guardrail you already defined in Bedrock — its topic, content, word,
sensitive-information and grounding policies — against prompts and responses.
Authenticate with static keys or an IAM role. The one distinctive option is
**PII action**: block, or **anonymise in place**, which is the only guardrail here
that redacts rather than refuses.

## Regex Replace

Ordered RE2 rewrite rules on the request **or** the response — one leg per
policy. Each rule sees the previous rule's output. No external service, fully
deterministic, and it does exactly what the pattern says and nothing more, which
is both its virtue and its limit.

## Combining them

A chain may hold several. TrustGuard on the request and a Bedrock guardrail
anonymising PII on the response is a common pair: the first refuses what should
not go out, the second cleans what comes back.
