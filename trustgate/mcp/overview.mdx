TrustGate's **MCP plane** aggregates [MCP registries](/trustgate/concepts/registries) into
one endpoint per [consumer](/trustgate/concepts/consumers). Agents connect once, see a
composed catalog of tools, prompts, and resources, and TrustGate applies the same tenancy,
auth, and observability as LLM traffic.

The transport is JSON-RPC over **streamable HTTP**. Copy the URL from the consumer
**Connect** tab:

```text
https://<mcp-host>/<consumer-slug>/mcp
```

<Note>
The data plane must reach each MCP server URL. SaaS cannot call private VPC endpoints unless
you expose them. Use [Hybrid](/neuraltrust/deployment/deployment-models) for internal MCP
servers.
</Note>

## Register an MCP server

1. Open **TrustGate** → **Registry** → **MCP**.
2. Connect a **catalog** server, or **Custom MCP** with your own URL.
3. Set **Authentication** as prompted: **None**, **Static header**, or
   **OAuth (forwarded)**.
4. Select **Test connection**, then **Connect** / **Save**.
5. Open the registry to browse the tools the server exposes.

Catalog servers that need extra config (client ID, secret, URL variables) collect those in
the connect panel before TrustGate registers them.

## Create an MCP consumer

1. Open **Consumers** → **New Consumer**.
2. Set **Protocol** to **MCP**.
3. Under **Auth**, choose:
   - **OAuth2** — agent login. Attach an IdP, or **Use NeuralTrust** (built-in login).
   - **API Key** — send `X-AG-API-Key` from the MCP client.
4. On **Routing**, bind MCP registries and optionally restrict tools per server.
5. Save, then copy the URL and snippets from **Connect**.

See [Auth](/trustgate/concepts/auth) and [Authorization](/trustgate/concepts/authorization/overview).

## What the agent sees

TrustGate fans `tools/list`, `resources/list`, and `prompts/list` out to the bound
servers and merges the results. Each `tools/call`, `resources/read`, or `prompts/get` goes
to the owning server.

If two servers expose the same tool name, TrustGate keeps names unique:

- Unique names pass through unchanged.
- On a collision, the tool is prefixed with the **registry name**.
- If that still collides, a short registry id or numeric suffix is added.

For **Static** consumers, the toolkit lives on the consumer. Leave tools unrestricted to
grant the whole server, or restrict to named tools. For **Identity-based** consumers, the
effective registries and tools are the union of the matched [roles](/trustgate/concepts/roles).
A role that binds an MCP registry without restricting tools grants that server fully.

If an upstream server is unavailable, TrustGate can skip it or fail the call depending on
how the consumer or role is configured.

## Upstream authentication

This is how TrustGate authenticates **to the MCP server**, not how the agent authenticates
to TrustGate.

| Authentication in the UI | Behavior |
|---|---|
| **None** | No upstream credential. |
| **Static header** | A fixed header (for example `Authorization`) on every call. |
| **OAuth (forwarded)** | Per-user OAuth. Registration **Automatic (DCR)** or **Manual** (client ID, authorize URL, token URL). |

With **OAuth (forwarded)**, the first call for a user without a stored credential returns a
connect link. After the user authorizes once, TrustGate vaults and refreshes the credential.

## Agent authentication

Agents authenticate to TrustGate as the MCP consumer.

| Consumer auth | How the agent connects |
|---|---|
| **OAuth2** / **Use NeuralTrust** | The MCP client runs OAuth (authorization code + PKCE). TrustGate advertises discovery at `/.well-known/oauth-authorization-server` and `/.well-known/oauth-protected-resource`. |
| **API Key** | The client sends `X-AG-API-Key`. On Private deployments, also send `X-AG-Gateway-Slug` unless the host already scopes the gateway. |

## Connect an agent

Same consumer URL for every client. Snippets are also on the consumer **Connect** tab
(Cursor, Claude Code, JSON).

| Agent | Page |
|---|---|
| Claude (claude.ai, Desktop, Cowork, Code) | [Claude](/trustgate/mcp/claude) |
| Cursor | [Cursor](/trustgate/mcp/cursor) |
| OpenAI Codex | [Codex](/trustgate/mcp/codex) |
| VS Code / GitHub Copilot | [VS Code](/trustgate/mcp/vscode) |
| Microsoft Copilot Studio | [Copilot Studio](/trustgate/mcp/copilot-studio) |

Do not use a TrustGuard collector `tgk_…` as an MCP credential.
