Every application on the MCP plane has one URL. What connects to it decides
which of two paths you take.

## An agent that already speaks MCP

Claude Code, Claude, Cursor, Codex, Gemini, VS Code — anything with an MCP client
— is pointed at the application's URL and nothing else. The Connect tab has the
exact snippet for each; they all reduce to one of these shapes:

<CodeGroup>
  ```bash Claude Code
  claude mcp add --transport http TrustGate https://<mcp-host>/<application-slug>/mcp
  ```

  ```json JSON config
  { "mcpServers": { "TrustGate": { "type": "http", "url": "https://<mcp-host>/<application-slug>/mcp" } } }
  ```
</CodeGroup>

How the agent authenticates follows from the application:

| Application's authentication | What happens on first connect |
|---|---|
| **An identity provider** | The client runs an OAuth sign-in; the person uses their own account. No key anywhere. |
| **An API key** | The client sends the key as `X-AG-API-Key`, `x-api-key`, or `Authorization: Bearer <key>`. The agent acts as the application. |

The [Employee portal](/trustgate/mcp/store) has its own URL and its own rule: a
person signs in there with their NeuralTrust login, and no key opens it.

With a per-person sign-in, the agent sees the application's servers — the same
set every caller of that application sees — and each person connects their own
upstream accounts on first use. Claude's organisation connector, Copilot Studio
and Windsurf have their own pages under [Integrations](/integrations/overview).

## Your own code: the TrustGate SDK

When you are writing the agent yourself, the URL is the easy part. MCP does not
carry **who a call runs as**, **which credential** it travels with, or **what to
do when an upstream account is not connected**, and the
[TrustGate SDK](/sdks/trustgate/overview) exists to answer those three. It needs
the application's key and nothing else: the gateway is found from the key.

<CodeGroup>
  ```python Python
  from trustgate import TrustGate

  agent = TrustGate().connect(requires=["search"])  # reads TRUSTGATE_API_KEY
  ```

  ```ts TypeScript
  import { TrustGate } from "@neuraltrust/trustgate"

  const agent = await new TrustGate().connect({ requires: ["search"] }) // reads TRUSTGATE_API_KEY
  ```
</CodeGroup>

`connect()` checks the run before it starts: the tools you need are there, and
every server has an account. From there, hand `agent.mcp` to a framework that
brings its own MCP client, or translate the tools for a model call.
