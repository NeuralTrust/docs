Analytics is Activity summed. Same events, one gateway, a time range, and a
toolbar that narrows to one application or reads **All traffic**.

## Tabs

| Tab | Answers |
|---|---|
| **Overview** | How much, how fast, how often refused. Requests, policy actions, errors, estimated cost, tokens; total latency split into gateway and upstream, with P95 and P99 for the gateway's own share. |
| **Policy** | What the policies did: requests denied, throttled, observed, masked — over time, per policy, and per security-engine reason. |
| **Cost** | Estimated spend, input and output tokens, over time, by model and by application. |
| **Users** | Traffic per person, where requests carried a user. |
| **LLM** | Per provider and per model: requests, tokens, cost. |
| **MCP** | Per server and per tool: requests, average and P95 latency, error rate; latency percentiles for tool calls. |

## Latency, read correctly

**Total latency** is end to end. **Gateway latency** is the part that is yours —
policy evaluation and routing — and it is the one to watch when adding a policy.
The rest is the provider's, and no gateway setting changes it. A total that grew
while gateway latency stayed flat is an upstream story.

## Cost, read correctly

Cost is estimated from tokens at the rate the gateway knows for that model:
[contract pricing](/trustgate/registry/models#contract-pricing) on the registry
where you set it, otherwise list price. Until you enter your contract, every
number here is list price, and so is every budget policy counting against it.

**Could not be priced** counts requests for models with no known rate — usually an
OpenAI-compatible endpoint or a custom model. They are real traffic with unknown
cost, not zero cost.

**Total savings** exists only when [smart routing](/trustgate/llm/routing#smart-routing)
is on. It is the spend avoided by sending each request to the cheapest tier that
could handle it, against what a premium tier would have cost. If it reads as an
**overspend**, a tier points at a model that costs more than the premium baseline
— a misconfiguration, and the number is telling you which way.

## Policy, read correctly

**Observed** counts what a policy in observe mode *would* have done. It is the
number to watch before switching a policy to enforce: an observed count you did
not expect is traffic you were about to block.
