---
title: "Playground"
description: "Chat through a real application with its real policies, and read exactly what the gateway did — before a client ever sees it."
---

The Playground sends a request through the gateway exactly as a client would:
through an application you pick, with that application's routing, restrictions
and policies applied. Nothing is simulated. The difference from production is
that you can read the decision in the same window.

## What you can test

Pick an LLM application — the Playground works against the Models plane. Choose a
model from what the application allows, or **Auto** when its strategy is
load-balanced. Send.

Each answer comes with the request's details: status, model and provider actually
selected, finish reason, latency, tokens, the gateway it ran on, and the policy
chain that ran. That last part is the point of the Playground: a request that
goes through is not proof a policy worked; the chain is.

## What a refusal looks like

The Playground says why, in the gateway's own terms rather than an HTTP code:

- **Request blocked** — a policy refused it. TrustGuard refusals name the detection:
  jailbreak, PII, a secret, toxicity, a gate rule, a multi-turn attack, indirect
  prompt injection, and so on.
- **Rate limit reached** — this application's limit, or the gateway's burst or
  monthly quota.
- **Routing not allowed** — the model is not in the application's allowed models,
  or the application has no registry for the model's provider.
- **Routing not configured** — the application's registries declare no default and
  the client named no model.
- **Model unavailable** — routed, but no registry serves that model, or the
  provider rejected the key for it.
- **Provider credential invalid** — the registry's stored key was rejected. Fix it
  in Registry.

Each of those points at a different page. That mapping is what makes the
Playground faster than reading Activity after the fact.

## What it does not do

It uses an internal session, not one of the application's keys, so nothing here
creates or exercises a credential a client would hold. It does not test the MCP
plane. And on a Hybrid gateway installed on a private network the console cannot
reach the data plane from here — test from a machine that can.
