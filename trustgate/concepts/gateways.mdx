---
title: "Gateways"
description: "A gateway is a running deployment and the boundary of everything else. Most teams need one; a second is for a genuinely separate environment, not for separating teams."
---

A **gateway** is the thing clients send requests to — a deployment with an LLM
endpoint and an MCP endpoint. It is also the boundary: registry entries,
applications, access, policies and traces belong to exactly one gateway, and
nothing crosses between two.

## One, usually

Applications separate what your teams built. Access separates people.
Instances separate production keys from staging keys on the same provider.
Policies separate rules. Every axis you might reach for a second gateway to get,
something smaller already provides — without a second set of credentials to
manage and a second Activity to watch.

A second gateway is for a **genuinely separate environment**: a different
network, a different data residency, a blast radius you want walled off. Those
are the cases where "nothing crosses between two" is the feature.

## SaaS or Private

Chosen at creation, and not changeable afterwards without recreating the gateway.

| | Where the data plane runs | When |
|---|---|---|
| **SaaS** | NeuralTrust hosts it. Nothing to install. | Default. |
| **Private** | You run it — Docker, Kubernetes or by hand — and register its public URL. The console still manages it. | Prompts must not leave your network, or you need fixed capacity and your own SLA. |

The console is identical either way. What differs is where a request physically
goes, and on Private, that the console cannot reach the data plane from the
outside — so the Playground and connection tests have to run from somewhere that
can. [Deployment](/neuraltrust/deployment/overview) covers running one.

## What the gateway itself holds

Its URLs, its environment label, its region and version, the Admin API
credentials that automate it, the identity providers and certificate authorities
it trusts, and its transport floor. All of that is [Settings](/trustgate/operate/settings).
Everything that routes *through* it is elsewhere — that is the whole point of the
[five objects](/trustgate/concepts/how-it-fits).

## Deleting one

Permanent, and everything it owns goes with it. If it is the organisation's only
gateway, nothing in TrustGate works until another exists.
