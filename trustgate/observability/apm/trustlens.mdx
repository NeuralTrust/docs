---
title: TrustLens Integration
---

The `trustlens` telemetry provider enables observability in TrustGate by sending trace-level data to the TrustLens platform. This includes inputs, outputs, timestamps, and additional context derived from request headers such as `User-Agent` and `Accept-Language`.

By parsing these headers, TrustGate can extract useful metadata like device type, operating system, browser, and locale—enhancing trace visibility and enabling deeper insights into user interactions. The TrustLens backend then aggregates and visualizes this data to help analyze gateway activity.

### Configuration

The telemetry provider is configured using the following parameters:

| Parameter | Type   | Required | Description                                                                                      |
|-----------|--------|----------|--------------------------------------------------------------------------------------------------|
| `url`     | string | Yes      | The full endpoint URL for the TrustLens trace API (e.g. `https://data.neuraltrust.ai/v1/trace`). |
| `token`   | string | Yes      | Bearer token used for authenticating telemetry submissions to TrustLens.                         |



### Trace Data Schema

Each interaction results in a POST request to TrustLens with a payload that conforms to the following schema:

| Field             | Description                                                 |
|-------------------|-------------------------------------------------------------|
| `trace_id`        | Gateway ID for the current trace.                           |
| `input`           | Raw input payload received by the gateway.                  |
| `output`          | Raw output response generated by the system.                |
| `start_timestamp` | Milliseconds since epoch when the request processing began. |
| `end_timestamp`   | Milliseconds since epoch when the response was finalized.   |
| `locale`          | Parsed locale information from the user-agent.              |
| `device`          | Device type (e.g., mobile, desktop) from the user-agent.    |
| `os`              | Operating system from the user-agent.                       |
| `browser`         | Browser type from the user-agent.                           |


### How It Works

Once TrustLens telemetry is enabled in your TrustGate gateway, observability becomes automatic and low-overhead:

1. **Provider Initialization**
The `trustlens` provider is initialized with your configuration—specifically the API endpoint (`url`) and access token (`token`). It also uses a built-in circuit breaker and HTTP client to ensure resilience during transmission.

2. **Metadata Collection**
For each incoming request (excluding `GET` requests), TrustGate collects key interaction metadata. This includes:
- Request input and response output
- Timestamps marking the start and end of processing
- Parsed headers such as `User-Agent` and `Accept-Language`, which reveal locale, device, OS, and browser information

3. **Trace Assembly and Delivery**
The collected data is structured into a telemetry "trace" conforming to the TrustLens schema and serialized as JSON. This trace is then transmitted to the TrustLens API (`https://data.neuraltrust.ai/v1/trace`) in real time.

4. **Fault Tolerance**
All outbound telemetry requests are wrapped with circuit breaker logic. If TrustLens is unavailable or returns an error, the system suppresses the failure and continues processing requests without interruption.

This architecture provides continuous insight into your gateway’s behavior, plugin performance, and user interactions—without requiring manual instrumentation or affecting runtime performance.



### Configuration Example:

```bash
curl -X POST "http://localhost:8080/api/v1/gateways" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "OpenAI Token Rate Limiter",
    "subdomain": "your-subdomain",
    "telemetry": {
        "config": [
            {
                "name": "trustlens",
                "settings": {
                    "url": "https://data.neuraltrust.ai/v1/trace",
                    "token": "YOUR_TOKEN"
                }
            }
        ]
    }
  }'
```

### Error Handling

The TrustLens telemetry provider includes structured error handling for common failure scenarios:

- **Missing configuration**:
Errors such as `"trustlens url is required"` or `"trustlens token is required"` are returned if mandatory configuration values are not provided.

- **HTTP request errors**:
Network failures, I/O issues, or non-2xx responses from the TrustLens API will be captured and returned as descriptive errors.

- **Circuit breaker protection**:
A circuit breaker wraps all outbound requests to TrustLens. This prevents repeated failures from impacting upstream gateway performance and ensures graceful degradation during external outages.
