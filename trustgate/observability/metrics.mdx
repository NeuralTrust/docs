---
title: "Metrics"
description: "TrustGate exposes Prometheus metrics for connections, request counts, and latency breakdowns from the proxy plane."
---

The proxy plane exports **Prometheus** metrics through a background worker, so scraping
never blocks request handling. Enable with `METRICS_ENABLED=true` (default).

## The metrics worker

Metrics are queued and flushed asynchronously:

| Variable | Default | Meaning |
|---|---|---|
| `METRICS_ENABLED` | `true` | Toggle metrics export. |
| `METRICS_QUEUE_SIZE` | `1000` | Buffered metric events. |
| `METRICS_WORKER_COUNT` | `1` | Worker goroutines draining the queue. |
| `METRICS_FLUSH_INTERVAL` | `5s` | How often the worker flushes. |

## Exposed metrics

| Metric | Type | What it tracks |
|---|---|---|
| `trustgate_connections` | gauge | In-flight connections. |
| `trustgate_requests_total` | counter | Total requests (labelled by outcome). |
| `trustgate_latency_ms` | histogram | End-to-end request latency. |
| `trustgate_detailed_latency_ms` | histogram | Latency split by phase (routing, policies, gateway). |
| `trustgate_upstream_latency_ms` | histogram | Time spent in the provider call. |

The detailed and upstream histograms let you separate **gateway overhead** from
**provider time** — useful for spotting whether latency is your policies or the upstream
model.

For per-request detail (model, tokens, cost, policy chain, attempts), use the
[telemetry stream](/trustgate/observability/telemetry).
