<Steps>
<Step title="Create a gateway">
Open **TrustGate → Overview**. With no gateway yet, creation opens on its own;
otherwise pick **New Gateway** from the selector. Name it and choose **SaaS**.

Choose **Private** only when prompts must not leave your network. You then run
the data plane yourself — Docker, Kubernetes or by hand, from the instructions the
console generates — and paste its public URL. [Deployment](/neuraltrust/deployment/overview)
covers what that involves. Everything else in this guide is the same either way.
</Step>

<Step title="Connect a provider">
Pick a provider, enter its credential, and **Test connection** before you save.
A credential that fails here fails later as provider errors your callers see, so
the test is the cheap moment to find out. [Model providers](/trustgate/registry/models)
has what each one asks for.
</Step>

<Step title="Send a request">
Pick one of the provider's models, type a question, send. The request goes
through the gateway you just created.
</Step>

<Step title="Read the trace">
Status, model, latency, tokens, trace id, response. This is the shape of every
row in [Activity](/trustgate/operate/activity) from now on.
</Step>
</Steps>

## The step that matters

The request you just sent used an internal session. **Nothing you have done so far
gives an application anything to call with.** For that:

1. Create an **[application](/trustgate/access/applications)** and add the provider
   to it. Its type follows — it now serves LLM traffic.
2. Issue it a **key**. It is shown once. Copy it somewhere safe.
3. Open **Connect** and copy the snippet. It already carries the right URL, the
   right header, and the right `model` value for the application's strategy.

The provider's credential never leaves the gateway. The application holds only its
own key, and rotating one never touches the other.

```bash
curl -X POST "https://<llm-host>/<application-slug>/v1/chat/completions" \
  -H "X-AG-API-Key: <application key>" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

Clients that only take a base URL and an API key — OpenAI or Anthropic SDKs,
Cursor, desktop chat apps — can send the same key as `Authorization: Bearer` or
`x-api-key` instead. Nothing else about them changes.
