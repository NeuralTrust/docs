title: "Model providers"
description: "Connect a model provider to a gateway from the console: credentials, a connection test before you save, and the contract pricing that makes cost reporting true."
---

On **Registry → Models**, **Add model** opens a panel listing the providers the
catalog knows. Pick one, fill in its credentials, test, save. The entry is
routable the moment it saves.

## What every provider asks for

| Field | Notes |
|---|---|
| **Name** | Shown in routes and traces. Use something you will recognise there — `openai-prod` beats `OpenAI`. |
| **API key** | Stored encrypted. On an existing entry it reads **(saved)**: leave it blank to keep the stored key, type a new one only to replace it. |
| **Base URL** | Optional on catalog providers, to point at a proxy or a regional endpoint. Required for OpenAI-compatible endpoints. |
| **Custom headers** | Any additional header the provider needs, added as name/value pairs. |

Under **Advanced**, **Authentication** chooses between a **Bearer API key** and a
**Custom header** for providers that want the credential somewhere other than
`Authorization`.

## Providers that ask for more

Some providers do not authenticate with a single key:

| Provider | What it needs |
|---|---|
| **Azure OpenAI** | The Azure endpoint and API version, then either an API key or a service principal — Tenant ID, Client ID and Client secret. |
| **Amazon Bedrock** | Access key ID, secret access key and region; a session token for temporary credentials. |
| **Vertex AI** | A GCP service-account JSON, uploaded or pasted, plus location. The project ID is filled from the JSON's `project_id`. An access token works instead for short-lived use. |
| **Local / OpenAI-compatible** | A base URL, and whatever auth that endpoint expects — including none. |

The panel validates the service-account JSON before it lets you save: it has to
be `type: "service_account"` and carry `client_email` and `private_key`.

## Test before you save

**Test connection** calls the provider with exactly what you typed and reports
the round trip — *Connection OK (412 ms)* — or why it failed.

Do it every time. A provider saved with a bad credential looks connected on the
card until real traffic hits it, and then the failure reaches your callers as
provider errors rather than as anything that looks like a configuration mistake.

The panel translates the common failures instead of passing the provider's raw
error through, so an Azure tenant that cannot be found, a client secret that is
invalid, an unauthorised client-credentials sign-in, a bad scope, an unreachable
endpoint and a timeout each read as themselves.

A few providers cannot be tested yet. The panel says so rather than pretending,
and for those it will not validate on save either.

## Contract pricing

Cost in **Analytics** and on every trace is only as true as the rates behind it.
By default TrustGate prices traffic at the provider's list rates. If you have a
negotiated contract, set it here so reporting matches your invoice.

| Field | Meaning |
|---|---|
| **List discount** | Percent off list, applied to every model on this provider. `20` means 20% off. |
| **Model override** | A model slug with explicit **Input $/1M** and **Output $/1M** rates. The slug accepts a trailing `*`, so `gpt-4o-mini*` covers a family. |

Overrides win where they match; the discount applies to everything else. Set the
discount alone if your contract is a flat percentage, and add overrides only for
models priced outside it.

Rates are USD per million tokens, and a negative rate is rejected.

## Custom models and backends

**Custom Model** and **Custom Backend** cover what the catalog does not list — a
self-hosted model, an internal inference service, an OpenAI-compatible vendor.
You supply the base URL, the authentication, and the name traffic will be routed
by.

## Instances

A provider card holds as many **instances** as you need: production and staging
keys, two Azure deployments, one key per team. Each is configured and tested on
its own, and each appears separately when routing is chosen.

## When something changes upstream

Rotating a key is an edit on the instance: paste the new key over the saved one
and test. Nothing else has to change — policies, applications and access all
point at the entry, not at the credential.
