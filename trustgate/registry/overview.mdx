---

**Registry** is the list of everything this gateway can reach. Nothing routes
anywhere until it exists here.

A registry entry says *what the destination is and how the gateway authenticates
to it*. It does not say who may use it — that is [Access](/trustgate/mcp/access), and
the Registry panels will tell you so when you look for it there.

## The two tabs

| Tab | What it holds |
|---|---|
| **Models** | Model providers the gateway routes inference to — OpenAI, Anthropic, Azure OpenAI, Bedrock, Vertex, Gemini, Mistral, Groq, Cohere, or any OpenAI-compatible endpoint. |
| **MCP** | MCP servers that expose tools and resources to agents. |

Each tab counts its entries, and the toolbar's **Search** and **Filter** apply to
the tab you are on.

## One gateway at a time

The **Gateway** selector sits in the page header, and everything below it belongs
to the gateway you picked. A provider connected on one gateway does not exist on
another — including its credentials.

If you have no gateway yet, Registry says so and offers to create one; you cannot
connect anything without one.

## Cards, not rows

Each card is one provider or server, and carries its status:

| Status | Meaning |
|---|---|
| **Connected** | Configured and routable. |
| **Available** | In the catalog, not configured here yet. |
| **Setup required** | MCP only: a catalog server waiting for a credential an admin has to supply. |
| **Last test failed** | The stored credentials did not work the last time the gateway tried them. |

**Last test failed** is worth acting on the moment you see it. The entry stays in
place and traffic keeps being routed to it, so the failure surfaces to callers as
provider errors rather than as anything obviously wrong with the gateway.

The card's button changes with that status — **Connect** or **Install** for
something not yet configured, **Settings** for something that is.

## Built-in and custom

**Origin** splits the catalog from what you added:

- **Built-in** entries come from the NeuralTrust catalog. For MCP, built-in also
  means users can install the server themselves from the Portal and sign in with
  their own account, with no admin step.
- **Custom** entries are the ones you registered by URL, by OpenAPI document, or
  as a custom model backend.

## Filters

| Filter | Tabs | Values |
|---|---|---|
| **Status** | all | Connected, Available, and Setup required on MCP |
| **Origin** | all | Built-in, Custom |
| **Category** | MCP | Built from the categories of the servers actually listed |
| **Capability** | Models | Chat, Embeddings, Rerank, Files, Images, Speech, Transcription |

**Capability** is the one to reach for when a routing decision depends on what a
provider can actually do: a provider that does not list *Embeddings* will not
serve an embeddings call no matter how the policy routes it.

## Instances

One provider card can hold several **instances** — separate configurations of the
same provider, each with its own credentials and its own name. Two Azure OpenAI
deployments, a production and a staging OpenAI key, one MCP server registered
twice against different accounts.

Open **Instances** from the card to add, edit or delete them. Each instance shows
how it authenticates:

| Pill | Meaning |
|---|---|
| **API key** | Everyone using this instance shares one stored key. |
| **User account** | Each person connects their own account the first time they use it. |
| **Shared account** | Machine-to-machine OAuth with a client ID and secret you supply. |
| **Caller's own token** | The gateway forwards the credential the caller arrived with. |
| **No authentication** | The destination needs none. |

A built-in server that people install themselves gets its default instance created
automatically the first time someone installs it — you do not have to make one.

## Access is not here

The **Access** tab inside a server's Instances panel, and the empty states across
Registry, all say the same thing: who may use an entry is decided on the
[Access](/trustgate/mcp/access) page, not here. Registry is about reachability and
credentials only.

## Deleting

Deleting an entry permanently removes it from the gateway and stops all routing
through it. There is no disable-and-keep: the dialog asks you to confirm because
the only way back is to configure it again.
