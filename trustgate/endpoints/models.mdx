description: "Call GET /{application}/v1/models to list the native model ids this application can actually call. This is gateway-owned discovery, not an upstream passthrough."
---

Clients that probe `client.models.list()` against an OpenAI-compatible `base_url` hit
this route. Auth and the application slug are the same as
[chat](/trustgate/getting-started/quickstart#call-from-your-application).

```bash
curl "https://<gateway-host>/<application-slug>/v1/models" \
  -H "X-AG-API-Key: <your-api-key>"

curl "https://<gateway-host>/<application-slug>/v1/models/gpt-4o-mini" \
  -H "X-AG-API-Key: <your-api-key>"
```

On a Private data plane, add `X-AG-Gateway-Slug` as in the chat snippets.

`GET /v1/models` returns `{ "object": "list", "data": [{ "id", "object": "model", "owned_by" }] }`.
`GET /v1/models/{id}` is **200** when that id is in the list, otherwise **404**.
Non-`GET` methods are **400**. Extra path tails (`/models/{id}/extra`) are **404**.

This is **not** a forward of the provider's `/v1/models` and **not** the admin models
catalog. The list is the union of native slugs the application can actually call.

The admin models catalog behind the console's model pickers is narrowed per registry to
the models its credentials can list — Azure OpenAI shows deployments, and **Custom /
OpenAI-compatible** lists the endpoint's live models. When the provider cannot be queried,
the full catalog is shown.

## What is listed

For each bound registry (plus fallbacks and load-balancing member models):

1. If the application has an allow-list, those ids are candidates.
2. If the policy is open, TrustGate expands from the provider catalog.
3. Only **native** slugs are kept — no `auto`, no `@provider/…`, no `pool:…`.
4. A slug is kept only when the registry's provider supports that modality (chat always;
   [embeddings](/trustgate/endpoints/embeddings) / [rerank](/trustgate/endpoints/rerank) only
   when the provider advertises them). Catalog flags win; otherwise the slug is inferred
   (`embed` → embeddings, `rerank` → rerank, else chat).

`owned_by` is the registry **provider** (for example `openai` or `anthropic`).

A listed id sent without a provider prefix resolves by walking the application's registries in
configured order; a name no registry serves is **404** `model_not_supported` on the chat
path — see [Model resolution](/trustgate/routing/model-resolution).

[Files](/trustgate/endpoints/files) have no model ids and are not listed.
[Images](/trustgate/endpoints/images) ids appear only when the catalog (or allow-list) includes
them and the application has an images-capable registry.
