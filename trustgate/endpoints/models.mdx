---
title: "Models"
description: "Discover the effective models exposed to a consumer through an OpenAI-compatible response."
---

The Models endpoint describes the effective model set for one
[consumer](/trustgate/concepts/consumers). TrustGate builds the response locally from the
consumer's registry bindings, model allowlists, and provider catalogs; it does not forward
the request to an upstream `/v1/models` endpoint.

## Endpoints

| Method | Path after consumer slug | Description |
|---|---|---|
| `GET` | `/v1/models` | List models allowed for this consumer |
| `GET` | `/v1/models/{id}` | Get one model card |

Only `GET` is accepted. Other methods return `400 invalid_request`.

## List models

```bash
curl "https://<llm-host>/<consumer-slug>/v1/models" \
  -H "X-AG-API-Key: <consumer-api-key>"
```

Example response:

```json
{
  "object": "list",
  "data": [
    {
      "id": "example-model",
      "object": "model",
      "owned_by": "example-provider"
    }
  ]
}
```

Models from all eligible registries are combined, deduplicated by ID, and sorted. Routing
references such as `auto` and pool aliases are not returned as model cards.

## Get one model

```bash
curl "https://<llm-host>/<consumer-slug>/v1/models/example-model" \
  -H "X-AG-API-Key: <consumer-api-key>"
```

TrustGate returns **404** when the model is not part of the consumer's effective model set.

## What the list represents

The response reflects:

- Registries attached directly to a Static consumer or made available through
  Identity-based roles.
- Per-registry model allowlists.
- Models known to the configured provider catalog.
- Whether the provider can serve the model as chat, embeddings, or rerank, inferred from
  catalog metadata and model identifiers.

<Note>
This is not a live, exhaustive provider catalog. TrustGate does not apply a separate
image/audio modality filter here; those model IDs appear only when they are part of the
configured catalog and effective consumer bindings.
</Note>

Copy the host and credentials from the consumer **Connect** tab. See
[Auth](/trustgate/concepts/auth).
