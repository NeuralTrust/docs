---
title: "Audio"
description: "Use OpenAI-shaped text-to-speech and transcription endpoints through an audio-capable registry."
---

TrustGate exposes separate endpoints for speech generation and audio transcription. Both
use consumer authentication and capability-aware registry selection.

## Endpoints

| Method | Path after consumer slug | Request body | Response |
|---|---|---|---|
| `POST` | `/v1/audio/speech` | JSON | Audio bytes |
| `POST` | `/v1/audio/transcriptions` | `multipart/form-data` | Provider transcription response |

Only `POST` is accepted. `/v1/audio/translations` is not a supported route and returns
**404**.

## Text-to-speech

```bash
curl -X POST "https://<llm-host>/<consumer-slug>/v1/audio/speech" \
  -H "X-AG-API-Key: <consumer-api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "tts-1",
    "voice": "alloy",
    "input": "TrustGate is ready."
  }' \
  --output speech.mp3
```

TrustGate returns the provider audio bytes with the upstream content type. For Mistral,
TrustGate maps supported voice fields and unwraps base64 audio responses into raw audio
bytes.

## Transcription

```bash
curl -X POST "https://<llm-host>/<consumer-slug>/v1/audio/transcriptions" \
  -H "X-AG-API-Key: <consumer-api-key>" \
  -F "model=whisper-1" \
  -F "file=@./recording.mp3"
```

Multipart payloads are preserved when forwarded.

## Supported registries

Audio routes can use OpenAI, Azure OpenAI, OpenAI-compatible, OpenRouter, Groq, and Mistral
registries when the configured client supports the requested audio capability.

TrustGate filters incompatible registries before routing. If no compatible registry is
available, it returns `503 no_backend_available`.

## Limitations

- Speech and transcription are not streaming endpoints.
- Models, voices, response formats, and transcription options remain provider-dependent.
- Consumer model allowlists are enforced for JSON and multipart requests.
- Unknown paths return **404**; unsupported methods return `400 invalid_request`.

Copy the host and credentials from the consumer **Connect** tab. See
[Auth](/trustgate/concepts/auth).
