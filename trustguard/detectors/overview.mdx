## The catalog

**Sides** is which directions a detector supports. **Masks** marks the one detector
that can rewrite the payload, which is what makes the **Transform** action
available.

### Data loss prevention

| Console card | Finds | Sides | Protocols | Masks |
|---|---|---|---|:--:|
| **Data Loss Prevention** | PII, and secrets — API keys, access tokens, JWTs, Stripe keys | Input, Output | All | ✅ |

### Content security

| Console card | Finds | Sides | Protocols | Masks |
|---|---|---|---|:--:|
| **Prompt Guard** | Jailbreaks and prompt injection from whoever is typing | Input, Output | All | — |
| **Toxicity Detection** | Abusive, hateful or unsafe language | Input, Output | All | — |
| **Moderation** | Content outside the subjects you allow, from thirteen predefined topics | Input, Output | All | — |
| **Custom Moderation** (Beta) | Content matching topics you define yourself, or a predefined one you customized | Input, Output | All | — |
| **URL Analyzer** | Injection and PII in pages the agent is asked to read | Input | LLM, MCP | — |
| **Document Analyzer** | Injection and PII in uploaded files, including scans via OCR | Input | LLM | — |

### Agent & MCP security

| Console card | Finds | Sides | Protocols | Masks |
|---|---|---|---|:--:|
| **Indirect Prompt Injection** | Hostile instructions in what a tool hands back, and in tool descriptions themselves | Input, Output | LLM, MCP | — |

## How much there is to configure

Most of these have a single setting. Knowing which is which saves you opening
each one:

| Configuration tab shows | Detectors |
|---|---|
| **Protection Sensitivity** and nothing else | Prompt Guard, Toxicity Detection, Indirect Prompt Injection |
| A list you choose from, plus **Protection Sensitivity** | Moderation (**Topics**), Custom Moderation (topics you define) |
| A list you choose from, and nothing else | Data Loss Prevention (**Data Categories**, **Custom rules**) |
| Two **linked detectors** you created earlier | URL Analyzer, Document Analyzer |

[Protection Sensitivity](/trustguard/detectors/content-security#protection-sensitivity)
is three preset cards — **Permissive**, **Balanced** (recommended), **Strict** —
not a number you type.

## How the catalog, detectors, and policies fit together

- A **catalog detector** is a fixed capability. You cannot change what it looks
  for, only how it is tuned.
- A [**detector**](/trustguard/concepts/detectors) is a named, reusable instance
  you create from a catalog entry. It is **detection-only** — it never decides
  what happens.
- A [**policy**](/trustguard/concepts/policies) references detectors in rules that
  set the action — **Monitor**, **Block**, **Transform** — and the phase, Input or
  Output.
- **Data Loss Prevention** is the only detector where **Transform** is valid.
  Selecting Transform for any other detector is rejected when you save the policy.

One detector can be referenced by many policies, which is the point: tune it once,
enforce it differently per collector.
