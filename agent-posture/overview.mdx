# Agent Posture

Agent Posture continuously discovers and monitors the AI agents deployed across your cloud environments, giving you a unified security and compliance view of your entire AI agent fleet.

## What Agent Posture does

For each connected environment, Agent Posture:

- **Discovers** all deployed AI agents, the models they use, and the datasets they have access to
- **Assesses** the security posture of each agent — tools, instructions, guardrails, authentication, access controls
- **Monitors** usage metrics — conversation counts, token consumption, latency, error rates, and tool invocations
- **Alerts** on security misconfigurations and policy violations

## Supported integrations

| Integration | Agents discovered | Usage metrics | Content filters |
|---|---|---|---|
| [Azure AI Foundry (v2)](/agent-posture/azure) | Azure AI Foundry agents | Via Log Analytics | RAI policies |
| [Azure OpenAI Classic (v1)](/agent-posture/azure) | OpenAI Assistants | Via Azure Monitor | Not exposed via API |
| [GCP Vertex AI](/agent-posture/gcp-vertex-ai) | Vertex AI Reasoning Engines | Via Cloud Monitoring | — |
| [Mistral AI](/agent-posture/mistral) | Mistral agents | Via Conversations API | Moderation API (manual) |
| [M365 Copilot & Copilot Studio](/agent-posture/m365-copilot) | Copilot Studio bots, M365 agents | Via Dataverse transcripts | Access control policies |

## How integrations work

Each integration uses a **service principal** or **service account** with read-only credentials that you configure once. Agent Posture uses these credentials to:

1. Enumerate all agents and associated resources in your environment
2. Collect security-relevant metadata (tools, instructions, guardrails, access controls)
3. Pull usage telemetry to track adoption and detect anomalies
4. Re-sync on a configurable schedule to reflect any changes

All credentials are encrypted at rest. Agent Posture never writes to or modifies your cloud resources — all access is strictly read-only.
