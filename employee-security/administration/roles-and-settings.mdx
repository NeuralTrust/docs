## Roles

Employee Security is a product in the platform's
[access model](/platform/users#access-model), with the usual three levels.
Each includes the one above it.

| Role | Can |
| --- | --- |
| **Viewer** | See employees, risk, simulations, training and email threats |
| **Editor** | Run phishing simulations and training: campaigns, assignments, templates and courses (create and submit for review). Triage email: decide on reports, quarantine or release, manage blocked and allowed senders |
| **Admin** | Configure integrations, sending domains, data retention and email security settings (auto-triage, the reporting mailbox). Approve or reject templates and courses. Manage API keys and SCIM. **View original** on an email |

Owners and Global Admins are Admins on every product.

User groups and **Add person** belong to the platform's user management:
creating or changing groups, and inviting people, need the **Admin** level on
IAM, whatever the Employee Security role.

The **Employee** role has no console product at all: it opens the employee
portal, where people take their training and see their points and badges.
Give it to everyone who should be trained but shouldn't see the console.

<Note>
**Approval is a separate step on purpose.** An Editor can write a template or
a course, but it goes out only once an Admin approves it. Give the Admin role
to the people accountable for what employees receive.
</Note>

## Settings

Organization-wide settings live in **Settings › Employee Security**. You need
the **Admin** role to change them.

### General

| Setting | Default | Effect |
| --- | --- | --- |
| Training **Expires after (months)** | 12 (3 to 120) | How long a passed course stays valid before it has to be taken again |
| Phishing campaigns **Duration (days)** | 14 (7 to 365) | How long a one-time campaign runs. It ends this many days after it starts, not when the last email is sent, so people back from leave still get it. Unsent simulations are then cancelled |

### API keys

API keys for TrustForce have one scope: **SCIM provisioning**. Create and
revoke them here; a key is shown only once. Keys from the retired report
add-ins show as **Report add-in (retired)** so you can revoke them.
