<p className="nt-lead">
  One app registration in your tenant, with one permission. TrustForce uses it
  to place simulations and training invitations in Outlook mailboxes and to
  watch those mailboxes for real threats.
</p>

## What the connection does

- **Delivers simulations and training invitations** straight into each
  mailbox through Microsoft Graph. There is no MX change, no connector, and no
  allow-listing in Exchange Online Protection or your email gateway.
- **Turns on [email security](/employee-security/email-security/overview).**
  Every employee's mailbox is watched for new mail, and suspicious messages
  can be quarantined, moved to Junk, or restored.
- **Reads the reporting mailbox**, if you set one up for Outlook's built-in
  Report button. See [Report suspicious email](/employee-security/report-suspicious-email#microsoft-365).

TrustForce does not read your directory through this connection. Your
employees come from [your NeuralTrust users, SCIM or your HR system](/employee-security/connect/directory).

## Before you start

- A Microsoft 365 tenant with Exchange Online mailboxes.
- Someone who can create app registrations and grant admin consent in
  Microsoft Entra ID.
- The **Admin** role for Employee Security in NeuralTrust.

## Set it up

<Steps>

<Step title="Register an app in Microsoft Entra ID">
In the [Microsoft Entra admin center](https://entra.microsoft.com), open
**Applications › App registrations** and click **New registration**. Give it a
name such as `NeuralTrust TrustForce` and choose **Accounts in this
organizational directory only (single tenant)**. No redirect URI is needed.
</Step>

<Step title="Add the permission">
In the new app, open **API permissions › Add a permission › Microsoft Graph ›
Application permissions**, select **Mail.ReadWrite**, and add it. Then click
**Grant admin consent** for your organization.

It must be an **application** permission, not a delegated one: TrustForce
works in the background, without anyone signed in.
</Step>

<Step title="Create a client secret">
Open **Certificates & secrets › Client secrets › New client secret**. Copy the
secret's **Value** now; Entra shows it only once. Note the expiry date: the
connection stops working when the secret expires.
</Step>

<Step title="Connect it in NeuralTrust">
Open **Settings › Employee Security › Integrations › Microsoft 365** and enter:

| Field | Where to find it |
| --- | --- |
| **Directory (tenant) ID** | The app's **Overview** page |
| **Application (client) ID** | The app's **Overview** page |
| **Client secret value** | The value you copied |

Click **Save and test**. The test checks that the token carries
**Mail.ReadWrite**; if consent is missing, it says so.
</Step>

</Steps>

The status turns **Connected**. Inbox scanning starts shortly after, and the
panel offers **Set up reporting** to configure Outlook's Report button.

<Note>
**Mail.ReadWrite** as an application permission covers every mailbox in the
tenant. TrustForce only uses the mailboxes of your active employees and the
reporting mailbox, if you set one.
</Note>

## Troubleshooting

| What you see | What to check |
| --- | --- |
| The test says the permission is missing | **Mail.ReadWrite** is an application permission and admin consent was granted |
| **Error** after it worked before | The client secret may have expired: create a new one and save it |
| A recipient shows **Not delivered** | The address has no Exchange Online mailbox in your tenant |
| **Email security › Settings** reports mailboxes that can't be watched | **View mailboxes** shows which. Check that they have an Exchange Online mailbox and that the connection still tests fine |
