Use this path for on-premises clusters and distributions without a dedicated provider guide.

## Required cluster capabilities

- A working default StorageClass, or an explicit `global.storageClass`.
- An ingress controller or Gateway implementation capable of exposing the generated hosts.
- DNS control for `global.domain`.
- TLS through cert-manager or pre-created Secrets.
- Outbound access to the image registry and configured LLM endpoints.
- In Hybrid, outbound access to NeuralTrust SaaS ClickStack and DataBridge when enabled.

```bash
kubectl version
kubectl get nodes
kubectl get storageclass
kubectl get ingressclass
```

## Ingress and TLS

Example for an installed NGINX controller and cert-manager:

```yaml
global:
  platform: kubernetes
  domain: platform.example.com
  ingress:
    className: nginx
    annotations:
      cert-manager.io/cluster-issuer: letsencrypt-prod
    tls:
      autoGenerate: false
      secretName: neuraltrust-tls
```

The chart's self-generated TLS is useful for testing but is not automatically trusted by browsers. Use your PKI or a public issuer for production.

## Storage and identity

PostgreSQL requires ReadWriteOnce storage by default. Confirm reclaim, expansion, backup, and topology behavior for the chosen StorageClass. Use workload identities offered by the distribution instead of static cloud credentials where possible.

For GPU Firewall workers, install the NVIDIA device plugin, label/taint the GPU pool, and apply [the explicit GPU overlay](/neuraltrust/deployment/firewall#gpu-workers).

Continue with [Kubernetes Hybrid](/neuraltrust/deployment/kubernetes/hybrid), or combine this platform setup with [External configuration](/neuraltrust/deployment/configuration#minimal-external).
