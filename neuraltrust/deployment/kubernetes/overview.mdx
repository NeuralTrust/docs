Use this path for clusters without a dedicated cloud guide. You run the Hybrid **data plane**; the control plane stays on NeuralTrust SaaS — see [Overview](/neuraltrust/deployment/overview).

## Required capabilities

- Worker capacity for your topology — [Cluster sizing](/neuraltrust/deployment/sizing) (Hybrid ~**3–4** × 8 vCPU / 16–32 GiB; External ~**4–5**)
- Default StorageClass (or set `global.storageClass`)
- Ingress or Gateway for generated hosts
- DNS for `global.domain` and TLS (cert-manager or pre-created Secrets)
- [Hybrid network allowlist](/neuraltrust/deployment/network) (config-sync / DataBridge egress + NeuralTrust inbound source IP), plus registry / LLM upstreams
- Reachable customer-managed PostgreSQL and Redis — [sizes](/neuraltrust/deployment/configuration#managed-stores)

```bash
kubectl version
kubectl get nodes
kubectl get storageclass
kubectl get ingressclass
```

## Ingress example

```yaml
global:
  platform: kubernetes
  domain: platform.example.com
  ingress:
    className: nginx
    annotations:
      cert-manager.io/cluster-issuer: letsencrypt-prod
    tls:
      autoGenerate: false
      secretName: neuraltrust-tls
```

## Install

Create the namespace, then the registry pull Secret ([Images](/neuraltrust/deployment/images)) and a TLS Secret if you are not using cert-manager:

```bash
kubectl create namespace neuraltrust
```

From there the install sequence — Secrets, values file, `helm upgrade --install`, verification — is the same on every provider:

- [Quick start](/neuraltrust/deployment/quickstart) for the commands
- [Hybrid walkthrough](/neuraltrust/deployment/hybrid-walkthrough) for the reasoning behind each step and what to check when it goes wrong
