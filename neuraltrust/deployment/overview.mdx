<Note>
This section covers the **Hybrid** deployment, where the Data Plane runs in your own cluster. On **SaaS**, NeuralTrust hosts everything and there is nothing to install — start from the [platform overview](/platform/overview).
</Note>

NeuralTrust ships the Data Plane as a single unified Helm chart — `neuraltrust-platform` — that runs on any Kubernetes cluster: AWS EKS, Google GKE, Azure AKS, Red Hat OpenShift, or vanilla Kubernetes (including on-prem).

For a Hybrid install you make two decisions:

1. **Where** does it run? → pick your cloud / platform
2. **What** do you bring? → the products (TrustGate, Firewall) plus a PostgreSQL and Redis. Metadata leaves your cluster over OpenTelemetry to the NeuralTrust SaaS collector; raw prompt/response bodies stay in your own PostgreSQL.

Everything else is covered by the chart's defaults.

## 1. Deployment models

| Model | Control Plane | Data Plane | Best for |
|---|---|---|---|
| [**SaaS**](./deployment-models#saas-fully-managed) *(fully managed)* | NeuralTrust SaaS | NeuralTrust SaaS | Fastest to value — nothing to install |
| [**Hybrid**](./deployment-models#hybrid-data-plane-in-your-environment) | NeuralTrust SaaS | Your cluster | Data residency / sovereignty requirements |

**SaaS has nothing to deploy.** The rest of this section is the **Hybrid** data-plane install. The full decision matrix and topology diagrams live in [Deployment models](./deployment-models).

The platform has two halves:

- **Control Plane** — UI, policy editor, scheduler, RBAC, the **OpenTelemetry collector**, the **ClickHouse** metadata store, and the **AlertEngine** (rule evaluation, alerts, SIEM forwarding). Always runs on NeuralTrust SaaS.
- **Data Plane** — the products that sit in your request path: **TrustGate** (the AI gateway) and the **Firewall** (prompt/response safety classifiers), plus their **PostgreSQL** and **Redis**. Runs in your cluster (Hybrid) or on NeuralTrust SaaS (SaaS).

Each product emits per-request **metadata over OpenTelemetry (OTLP)** to the NeuralTrust SaaS collector, which lands it in ClickHouse for the AlertEngine and dashboards. Raw prompt/response bodies are written to a **PostgreSQL** store — in **Hybrid** that Postgres lives in your cluster, so your prompt and response data never leaves your environment; in **SaaS** everything runs on NeuralTrust SaaS.

## What gets deployed

In **SaaS**, all of these are hosted and managed by NeuralTrust — nothing is deployed in your environment. In **Hybrid**, the chart deploys the data-plane components in your cluster; the Control Plane (including the OTel collector, ClickHouse, and the AlertEngine) always runs on NeuralTrust SaaS:

| Component | Purpose | Deployed in your cluster (Hybrid) |
|---|---|---|
| TrustGate (admin + gateway + actions) | AI gateway | ✅ *(typical)* |
| Firewall (gateway + 5 workers) | In-cluster prompt/response safety — CPU or GPU workers | ✅ |
| PostgreSQL | TrustGate admin metadata **and** the raw prompt/response store | ✅ *(or external)* |
| Redis | TrustGate / Firewall cache and session store | ✅ *(or external)* |
| OpenTelemetry collector | Receives product metadata, lands it in ClickHouse | — *(on NeuralTrust SaaS)* |
| ClickHouse | Metadata store for alerts and dashboards | — *(on NeuralTrust SaaS)* |
| AlertEngine | Rule evaluation, alert dedup, SIEM forwarding | — *(on NeuralTrust SaaS)* |
| Control Plane API + UI + Scheduler | Dashboards, RBAC, policy distribution | — *(on NeuralTrust SaaS)* |

For the complete image list, including tags, replicas, and resource footprints, see [Image catalog](./images).

## Configurable infrastructure

In a Hybrid install you bring two stores in your cluster:

- **PostgreSQL** — TrustGate admin metadata and the raw prompt/response store.
- **Redis** — TrustGate / Firewall cache and sessions.

Each can be **in-cluster** (default — the chart deploys and manages StatefulSets, PVCs, and credentials) or **external** (point the chart at a managed service such as RDS, Cloud SQL, Azure Database for PostgreSQL, or managed Redis).

The **OpenTelemetry collector** and **ClickHouse** are not deployed in your cluster — products send metadata over OTLP to the NeuralTrust SaaS collector. See [Configuration scenarios › External infrastructure](./configuration#external-infrastructure-only).

## Detailed component reference

Each component below is documented for its responsibilities and security posture. For *how* to deploy them, follow the per-cloud guide above.

### Data Plane

The Data Plane is the set of products that sit in your request path and manage your private data — TrustGate, the Firewall, and their stores.

**TrustGate (AI gateway)**
- Real-time validation of AI traffic against configured security policies.
- API key management and JWT-based authentication.
- Horizontal autoscaling against incoming volume.

**Firewall (gateway + workers)**
- In-cluster prompt/response safety classifiers (CPU or GPU workers).
- Runs entirely within your environment.

**Telemetry export (OpenTelemetry)**
- Each product emits per-request **metadata over OTLP** — verdicts, counters, finding labels, latency, cost — to the NeuralTrust SaaS collector.
- No raw prompt/response text is in the metadata stream.
- No Kafka and no in-cluster ClickHouse: the collector and metadata store are on NeuralTrust SaaS.

**Raw payload store (PostgreSQL)**
- Raw prompt/response bodies are written to a PostgreSQL store in your cluster (e.g. the Firewall's `trustguard_data`).
- Used only so you can view prompt/response in the platform; the UI fetches raw **on demand** by `(team_id, trace_id)`.
- In Hybrid, raw data never leaves your environment.

<Note>
PostgreSQL and Redis are the stores you bring in a Hybrid data plane. Deploy in-cluster or point at managed services (RDS, Cloud SQL, Azure Database for PostgreSQL, managed Redis).
</Note>

### Control Plane

The Control Plane provides centralized management and advanced AI security capabilities. It always runs on NeuralTrust SaaS.

**API**
- Backbone for all Control Plane operations and customer interactions.
- Powers the NeuralTrust dashboard and customer interfaces.
- Multi-tenant architecture with strict environment isolation.
- Global orchestration across multiple customer Data Plane deployments.

**Application (UI)**
- Real-time dashboards for AI security and performance insights.
- Cross-environment analytics without compromising individual data privacy.
- Centralized alert configuration and notification management.

**Scheduler**
- Schedules and orchestrates TrustTest execution jobs across customer environments.
- Coordinates TrustScan security analysis jobs and vulnerability assessments.
- Manages the timing and execution of AI testing and scanning workflows.

**OpenTelemetry collector + ClickHouse**
- The collector receives product metadata over OTLP and lands it in ClickHouse.
- Materialized views fan it out into the per-product event tables the AlertEngine and dashboards read.

**AlertEngine**
- Evaluates predefined and custom detection rules over the metadata in ClickHouse.
- Deduplicates alerts, forwards findings to customer SIEMs, and serves the Telemetry UI (Alerts / Logs / Integrations).
- Never reads raw payloads — drill-down is a separate on-demand fetch.

**Database (PostgreSQL)**
- Stores only basic operational data for CRUD operations (Control Plane and AlertEngine state).
- Never stores customer's sensitive AI monitoring data.
- Configuration management and user management for accounts, permissions, and authentication.

## Data flow & privacy

This describes the **Hybrid** model, where NeuralTrust's architecture ensures complete data sovereignty while enabling comprehensive AI security through privacy-preserving data flows. (In **SaaS**, this flow runs entirely within NeuralTrust SaaS.)

**AI application data flow (your environment):**

1. AI applications route through **TrustGate** and the **Firewall** for real-time validation against configured security policies.
2. Each product emits per-request **metadata over OpenTelemetry (OTLP)** — verdicts, finding labels, latency, cost, correlation ids — to the **NeuralTrust SaaS OTel collector**. No raw prompt/response text is in this stream.
3. The collector lands metadata in **SaaS ClickHouse**, where materialized views populate the per-product event tables.
4. The **AlertEngine** (SaaS) evaluates detection rules over those tables, raises and deduplicates alerts, and forwards findings to your SIEMs.

**Raw prompt/response (stays in your environment):**

- If you want to view prompt/response in the platform, the products write raw bodies to a **PostgreSQL** store in your cluster.
- The platform resolves raw **on demand** by `(team_id, trace_id)` from your data plane — raw data never crosses the VPC boundary in Hybrid.

**Policy management flow:**

- The **TrustGate admin** service exposes security policies, routing rules, rate limits, and access controls that govern gateway behavior.

**Cross-VPC security operations (privacy-safe only):**

- **TrustTest** runs on the NeuralTrust Control Plane for comprehensive red-teaming, against your data-plane endpoints.
- **TrustScan** performs analysis within your Data Plane using your complete data.
- Only aggregated, anonymized security insights cross the VPC boundary.
- Customer prompts, responses, and user data never leave your environment for vulnerability scanning.

> **Why TrustTest runs in the Control Plane**
>
> TrustTest operates exclusively in NeuralTrust's Control Plane infrastructure to maintain a centralized, continuously updated jailbreak database. New jailbreak techniques emerge daily; maintaining an up-to-date threat intelligence database requires continuous research and monitoring. By running TrustTest centrally, all customers immediately benefit from the latest red-teaming capabilities without independently cataloging new attack methods.
