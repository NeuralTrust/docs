---
title: Hybrid
description: Install Hybrid runtime workloads on EKS.
---

## Prepare

```bash
kubectl get nodes
kubectl get storageclass
kubectl create namespace neuraltrust
```

Install the EBS CSI driver and AWS Load Balancer Controller before using the defaults below. Create the NeuralTrust registry pull Secret or configure an internal mirror.

## Values

```yaml
global:
  deploymentMode: hybrid
  platform: aws
  domain: platform.example.com
  storageClass: gp3
  clickstack:
    existingSecret:
      name: clickstack-otlp-token
      key: OTEL_EXPORTER_OTLP_HEADERS
  ingress:
    className: alb
    aws:
      scheme: internet-facing
      targetType: ip
      certificateArn: arn:aws:acm:<REGION>:<ACCOUNT_ID>:certificate/<ID>
```

For private RDS/Aurora and ElastiCache, use [managed stores](/neuraltrust/deployment/configuration#managed-stores). Prefer IRSA and the chart's supported IAM authentication values where your selected services support them.

## Install

```bash
helm upgrade --install neuraltrust-platform \
  oci://europe-west1-docker.pkg.dev/neuraltrust-app-prod/helm-charts/neuraltrust-platform \
  --namespace neuraltrust \
  -f values-eks-hybrid.yaml

kubectl get pods,ingress -n neuraltrust
```

Point Route 53 or your DNS provider at the ALB hostname after it is provisioned. Connect the resulting data-plane endpoint through [Advanced](/platform/advanced).

## Verify

```bash
kubectl get ingress -n neuraltrust -o wide
kubectl describe ingress -n neuraltrust
kubectl get events -n neuraltrust --sort-by=.lastTimestamp
```

For registry credentials, OTLP headers, and optional DataAgent enrollment, use [Secrets](/neuraltrust/deployment/secrets).
