NeuralTrust supports Amazon EKS for Hybrid deployments.

## Cluster baseline

```bash
eksctl create cluster \
  --name neuraltrust \
  --region <REGION> \
  --managed \
  --node-type m6i.2xlarge \
  --nodes 3

aws eks update-kubeconfig \
  --name neuraltrust \
  --region <REGION>
```

Install the AWS Load Balancer Controller when using ALB ingress. Associate an IAM OIDC provider and use IRSA for workloads that access RDS, ElastiCache, Secrets Manager, or other AWS APIs.

## AWS choices

- **Ingress:** AWS Load Balancer Controller with `global.ingress.className: alb`.
- **TLS:** ACM certificate through `global.ingress.aws.certificateArn`.
- **Storage:** EBS CSI `gp3` for single-writer PVCs; EFS only where shared access is required.
- **Datastores:** private RDS/Aurora PostgreSQL and ElastiCache endpoints.
- **Identity:** IRSA, including optional chart-supported IAM database/cache authentication.

Configure public or internal ALB behavior with `global.ingress.aws.scheme`, `targetType`, `groupName`, and provider annotations.

## GPU workers

Create a managed GPU node group and label/taint it consistently with your Firewall overlay:

```bash
eksctl create nodegroup \
  --cluster neuraltrust \
  --region <REGION> \
  --name firewall-gpu \
  --node-type g4dn.xlarge \
  --nodes 1 \
  --node-labels accelerator=nvidia \
  --node-taints nvidia.com/gpu=present:NoSchedule
```

Use an EKS GPU-optimized AMI or install the NVIDIA device plugin, then follow [Firewall GPU workers](/neuraltrust/deployment/firewall#gpu-workers).
