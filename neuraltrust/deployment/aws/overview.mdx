Use Amazon EKS for the Hybrid **data plane**. The control plane stays on NeuralTrust SaaS — see [Overview](/neuraltrust/deployment/overview).

## Cluster baseline

Defaults are a comfortable starting point for Hybrid (**3–4** × `m6i.2xlarge`).
External usually wants **one extra node**. Right-size later — see
[Cluster sizing](/neuraltrust/deployment/sizing).

```bash
eksctl create cluster \
  --name neuraltrust \
  --region <REGION> \
  --managed \
  --node-type m6i.2xlarge \
  --nodes 3

aws eks update-kubeconfig \
  --name neuraltrust \
  --region <REGION>
```

Install the AWS Load Balancer Controller for ALB ingress. Use IRSA for AWS API access.

## AWS choices

- **Ingress / TLS:** ALB (`global.ingress.className: alb`) + ACM (`certificateArn`)
- **Datastores:** private RDS/Aurora and ElastiCache — [minimum sizes](/neuraltrust/deployment/configuration#managed-stores)
- **Network:** [Hybrid network allowlist](/neuraltrust/deployment/network) (config-sync / DataBridge egress + NeuralTrust inbound source IP); also registry, LLM upstreams, your stores

## GPU workers (optional)

Only if you run Firewall on GPU — see [Firewall](/neuraltrust/deployment/firewall#gpu-workers).

Continue with [EKS Hybrid](/neuraltrust/deployment/aws/hybrid).
