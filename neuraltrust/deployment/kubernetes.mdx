title: Install on Kubernetes
description: Deploy the full NeuralTrust Platform (Data Plane, Control Plane, TrustGate, optional Firewall) to any Kubernetes cluster with a single Helm chart.

NeuralTrust ships as a single unified Helm chart — `neuraltrust-platform` — that installs every Data Plane and Control Plane component, plus TrustGate and the optional NeuralTrust Firewall. Every component is independently toggleable, so you can run the full stack or only the parts you need.

This page is the canonical install guide. For cloud-specific setup of the cluster itself, see [AWS (EKS)](./aws), [Azure (AKS)](./azure), [GCP (GKE)](./gcp), or [OpenShift](./openshift).

## What gets installed

| Component | Purpose |
|---|---|
| **TrustGate** | Low-latency AI gateway with plugin system and admin API |
| **Control Plane** | Management API, product UI, and scheduler |
| **Data Plane** | Telemetry/analytics API and Kafka workers |
| **Firewall** *(optional)* | Prompt and response safety — gateway + ML worker pool (CPU or GPU) |
| **ClickHouse** | Analytics database (in-cluster or external) |
| **Kafka** | Event streaming (in-cluster or external) |
| **PostgreSQL** | Relational store (in-cluster or external) |

<Note>
The Firewall subchart is **off by default**. Enable it when TrustGate or the Control Plane need in-cluster prompt/response safety. See [Firewall deployment](./firewall).
</Note>

## Prerequisites

- A Kubernetes cluster, version 1.24 or newer (EKS, AKS, GKE, OpenShift 4.10+, or any conformant distribution).
- [Helm](https://helm.sh/docs/intro/install/) 3.8 or newer (OCI registry support).
- `kubectl` (or `oc` on OpenShift) configured against the target cluster.
- A NeuralTrust-issued Google Artifact Registry JSON key (`gcr-keys.json`) for pulling private container images.
- A base domain you control for ingress (or wildcard DNS for OpenShift Routes).

**Resource baseline** (full stack, in-cluster infrastructure, no Firewall):

| Resource | Recommended starting point |
|---|---|
| Worker nodes | 3 nodes, 4 vCPU / 16 GiB RAM each |
| Persistent storage | 100 GiB (ClickHouse 50 GiB, Kafka 10 GiB, PostgreSQL 20 GiB, headroom) |
| Storage class | `ReadWriteOnce`, dynamic provisioning enabled |

GPU Firewall workers add their own node pool requirements — see [Firewall deployment](./firewall).

## Quick start

This installs the full platform with auto-generated secrets, in-cluster infrastructure, and the chart's default ingress for your platform.

<Steps>
  <Step title="Create the namespace and image pull secret">
    NeuralTrust container images are hosted in a private Google Artifact Registry. Use the JSON key file you received from NeuralTrust.

    ```bash
    kubectl create namespace neuraltrust

    kubectl create secret docker-registry gcr-secret \
      --docker-server=europe-west1-docker.pkg.dev \
      --docker-username=_json_key \
      --docker-password="$(cat path/to/gcr-keys.json)" \
      --docker-email=admin@neuraltrust.ai \
      -n neuraltrust
    ```

    On OpenShift, use `oc new-project neuraltrust` instead.
  </Step>

  <Step title="Install from the OCI registry">
    Replace `<VERSION>` with a release version (e.g. `1.10.0`). The full list of releases is available on [GitHub](https://github.com/NeuralTrust/neuraltrust-platform/releases).

    ```bash
    helm upgrade --install neuraltrust-platform \
      oci://europe-west1-docker.pkg.dev/neuraltrust-app-prod/helm-charts/neuraltrust-platform \
      --version <VERSION> \
      --namespace neuraltrust \
      --set global.platform=aws \
      --set global.domain=platform.example.com
    ```

    Set `global.platform` to match your environment: `aws`, `gcp`, `azure`, `openshift`, or `kubernetes`. The chart auto-configures ingress, security contexts, and provider-specific annotations.
  </Step>

  <Step title="Wait for pods to become ready">
    ```bash
    kubectl get pods -n neuraltrust -w
    ```

    Initial install typically takes 3–5 minutes. All pods should reach `Running` (or `Completed` for one-shot Jobs).
  </Step>

  <Step title="Get the ingress endpoints">
    ```bash
    kubectl get ingress -n neuraltrust
    # On OpenShift with the default Routes provider:
    # oc get routes -n neuraltrust
    ```

    Point DNS for the hosts shown to the load balancer / router address. The Control Plane UI is typically reachable at `https://app.<your-domain>` and the Data Plane API at `https://data-plane-api.<your-domain>`.
  </Step>
</Steps>

<Tip>
All platform secrets are auto-generated on first install and preserved on every subsequent `helm upgrade`. You don't need to manage JWT secrets, database passwords, or server keys manually unless you want to. See [Secrets management](./secrets).
</Tip>

## Customizing the install

The default install is opinionated but every value is overridable. Copy the minimal values template and override only what you need:

```bash
curl -sLO https://raw.githubusercontent.com/NeuralTrust/neuraltrust-platform/main/values-required.yaml
cp values-required.yaml my-values.yaml
```

Edit `my-values.yaml`, then deploy:

```bash
helm upgrade --install neuraltrust-platform \
  oci://europe-west1-docker.pkg.dev/neuraltrust-app-prod/helm-charts/neuraltrust-platform \
  --version <VERSION> \
  --namespace neuraltrust \
  -f my-values.yaml
```

For a side-by-side comparison of every values file the chart ships, see [Configuration scenarios](./configuration).

### Platform selector

Set `global.platform` to match your target. The chart auto-configures ingress, security contexts, and annotations.

| Platform | `global.platform` | Default ingress | Notes |
|---|---|---|---|
| AWS (EKS) | `aws` | ALB via AWS LB Controller | Supports ACM, WAF, target groups |
| GCP (GKE) | `gcp` | GCE load balancer | Supports NEG, PSC, managed certificates |
| Azure (AKS) | `azure` | Application Gateway (AGIC) | Supports AGIC SSL, WAF policies |
| OpenShift | `openshift` | Routes (default) or Ingress | See [OpenShift guide](./openshift) |
| Generic K8s | `kubernetes` | Bring your own controller | No cloud-specific annotations |

```yaml
global:
  platform: "aws"
  domain: "platform.example.com"
```

### Component toggles

Every component can be enabled or disabled independently:

```yaml
neuraltrust-data-plane:
  dataPlane:
    enabled: true       # Data Plane API + workers

neuraltrust-control-plane:
  controlPlane:
    enabled: true       # Control Plane API + UI + scheduler

trustgate:
  enabled: true         # TrustGate AI gateway

neuraltrust-firewall:
  firewall:
    enabled: false      # Firewall gateway + workers (off by default)
```

### Infrastructure: in-cluster or external

ClickHouse, Kafka, and PostgreSQL can each be deployed in-cluster (default) or pointed at an existing managed instance.

<Tabs>
  <Tab title="In-cluster (default)">
    ```yaml
    infrastructure:
      clickhouse:
        deploy: true
      kafka:
        deploy: true

    neuraltrust-control-plane:
      infrastructure:
        postgresql:
          deploy: true
    ```

    Best for development, staging, and most production workloads. The chart manages PVCs, service discovery, and credentials.
  </Tab>
  <Tab title="External services">
    ```yaml
    infrastructure:
      clickhouse:
        deploy: false
        external:
          host: "clickhouse.example.com"
          port: "8123"
          user: "neuraltrust"
          password: ""  # inject via --set or pre-created secret
          database: "neuraltrust"

      kafka:
        deploy: false
        external:
          bootstrapServers: "kafka.example.com:9092"

    neuraltrust-control-plane:
      infrastructure:
        postgresql:
          deploy: false
      controlPlane:
        components:
          postgresql:
            secrets:
              host: "postgres.example.com"
              port: "5432"
              user: "neuraltrust"
              password: ""  # inject via --set or pre-created secret
              database: "neuraltrust"
    ```

    Use when you already operate managed analytics, streaming, or relational stores. The Helm chart only deploys NeuralTrust workloads in this mode.
  </Tab>
</Tabs>

### Corporate proxy

For environments behind a forward proxy:

```yaml
global:
  proxy:
    enabled: true
    httpProxy: "http://proxy.corp.example:3128"
    httpsProxy: "http://proxy.corp.example:3128"
    noProxy: "localhost,127.0.0.1,.cluster.local,.svc"
```

### TLS certificates

| Method | When to use |
|---|---|
| **Self-signed** (default) | Quick starts — chart creates a shared TLS secret automatically |
| **Pre-existing secrets** | You manage certificates externally and reference them by `secretName` |
| **cert-manager** | Automatic issuance via Let's Encrypt or an internal CA |

Configuration lives under `global.ingress.tls.*` in `values.yaml`.

## Alternative install methods

<Tabs>
  <Tab title="Tarball from a GitHub Release">
    ```bash
    curl -sLO https://github.com/NeuralTrust/neuraltrust-platform/releases/download/v<VERSION>/neuraltrust-platform-<VERSION>.tgz

    helm upgrade --install neuraltrust-platform ./neuraltrust-platform-<VERSION>.tgz \
      --namespace neuraltrust --create-namespace \
      -f my-values.yaml
    ```

    Use when the cluster cannot reach the OCI registry but can fetch GitHub release assets.
  </Tab>
  <Tab title="Clone source at a release tag">
    Use this only when you need to inspect or modify the chart itself.

    ```bash
    git clone --branch v<VERSION> --depth 1 https://github.com/NeuralTrust/neuraltrust-platform.git
    cd neuraltrust-platform
    helm dependency update

    helm upgrade --install neuraltrust-platform . \
      --namespace neuraltrust --create-namespace \
      -f my-values.yaml
    ```
  </Tab>
</Tabs>

## Upgrading

```bash
helm upgrade neuraltrust-platform \
  oci://europe-west1-docker.pkg.dev/neuraltrust-app-prod/helm-charts/neuraltrust-platform \
  --version <NEW_VERSION> \
  --namespace neuraltrust \
  -f my-values.yaml
```

Auto-generated secrets and persistent volumes are preserved automatically. Always check the [release notes](https://github.com/NeuralTrust/neuraltrust-platform/releases) for version-specific migration steps before upgrading.

## Uninstalling

```bash
helm uninstall neuraltrust-platform --namespace neuraltrust
```

<Warning>
Persistent Volume Claims are retained by default to prevent accidental data loss. Delete them manually with `kubectl delete pvc -n neuraltrust --all` once you've confirmed the data is no longer needed.
</Warning>

## Verification

```bash
# All pods Running or Completed
kubectl get pods -n neuraltrust
```

## Troubleshooting

### Pods not starting

```bash
kubectl describe pod <pod-name> -n neuraltrust
kubectl logs <pod-name> -n neuraltrust
kubectl get events -n neuraltrust --sort-by='.lastTimestamp'
```

### Common issues

| Symptom | Likely cause | Fix |
|---|---|---|
| `ImagePullBackOff` | Missing or wrong image pull secret | Recreate `gcr-secret` with the JSON key from NeuralTrust |
| ClickHouse connection fails | Wrong host in Data Plane config | Verify `neuraltrust-data-plane.dataPlane.components.clickhouse.host` |
| Kafka connection fails | Wrong bootstrap servers | Check `KAFKA_BOOTSTRAP_SERVERS` env in Data Plane pods |
| PostgreSQL connection fails | Wrong host or credentials | Verify `neuraltrust-control-plane.controlPlane.components.postgresql.secrets` |
| Secret not found | Pre-generated secrets missing | `kubectl get secrets -n neuraltrust`. See [Secrets management](./secrets) |
| TrustGate firewall env vars stale | Pods not restarted after secret change | `kubectl rollout restart deployment/trustgate-control-plane -n neuraltrust` |

### Kafka cluster ID mismatch

If you see `Invalid cluster.id in: /bitnami/kafka/data/meta.properties` after a reinstall:

```bash
kubectl scale statefulset kafka-broker -n neuraltrust --replicas=0
kubectl delete pvc data-kafka-broker-0 -n neuraltrust
kubectl scale statefulset kafka-broker -n neuraltrust --replicas=1
```

This deletes existing Kafka data — only do it on dev/staging or when you have explicit confirmation that the data can be discarded.
