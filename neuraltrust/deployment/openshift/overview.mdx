NeuralTrust supports OpenShift with native Routes or Kubernetes Ingress. The current chart includes `values-openshift.yaml` as the canonical Hybrid starting point.

## Prepare a project

```bash
oc login https://api.<cluster>:6443
oc new-project neuraltrust
oc get storageclass
```

Create and link the NeuralTrust registry pull Secret:

```bash
oc secrets link default gcr-secret --for=pull -n neuraltrust
oc secrets link builder gcr-secret --for=pull -n neuraltrust
```

Create `gcr-secret` first using credentials provided by NeuralTrust, or configure your internal mirror.

## OpenShift choices

- `global.platform: openshift`
- `global.ingress.provider: openshift` for native Routes.
- `global.domain` should normally match the cluster applications wildcard suffix.
- `global.storageClass` should reference a ReadWriteOnce-capable class for PostgreSQL.
- Keep default restricted security behavior; grant additional SCC permissions only to workloads that demonstrably require them.

GPU Firewall workers can require `hostIPC` and GPU device access. Review the SCC impact before enabling the [GPU overlay](/neuraltrust/deployment/firewall#gpu-workers).

## TLS

Routes can use router-managed edge TLS or a supplied certificate, depending on cluster policy. For Ingress instead, set the provider/resource type and use the installed ingress controller plus cert-manager.

Continue with [OpenShift Hybrid](/neuraltrust/deployment/openshift/hybrid), or apply [External values](/neuraltrust/deployment/configuration#minimal-external) with OpenShift routing and security overrides.
