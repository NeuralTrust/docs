Use OpenShift Routes (or Kubernetes Ingress) for the Hybrid **data plane**. The control plane stays on NeuralTrust SaaS — see [Overview](/neuraltrust/deployment/overview). Start from the chart's tracked [`values-openshift.yaml`](https://github.com/NeuralTrust/neuraltrust-platform/blob/main/values-openshift.yaml), which you get by unpacking the chart or from the [chart repository](https://github.com/NeuralTrust/neuraltrust-platform). There is also an [OpenShift guide](https://github.com/NeuralTrust/neuraltrust-platform/blob/main/README-OPENSHIFT.md) maintained next to the chart.

## Prepare a project

```bash
oc login https://api.<cluster>:6443
oc new-project neuraltrust
oc get storageclass
```

Create and link the registry pull Secret:

```bash
oc secrets link default gcr-secret --for=pull -n neuraltrust
oc secrets link builder gcr-secret --for=pull -n neuraltrust
```

## OpenShift choices

- Worker capacity for your topology — [Cluster sizing](/neuraltrust/deployment/sizing) (Hybrid ~**3–4** × 8 vCPU / 16–32 GiB; External ~**4–5**; right-size later)
- [Hybrid network allowlist](/neuraltrust/deployment/network) for config-sync / DataBridge egress and the NeuralTrust inbound source IP
- `global.platform: openshift` and `global.ingress.provider: openshift` for Routes
- `global.domain` usually matches the apps wildcard suffix
- Customer-managed PostgreSQL and Redis — [minimum sizes](/neuraltrust/deployment/configuration#managed-stores)
- Keep restricted SCCs; grant extras only when a workload requires them (for example GPU Firewall)
