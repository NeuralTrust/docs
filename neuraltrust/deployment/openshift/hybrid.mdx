## Prepare TrustGate

Use Kubernetes for production-grade OpenShift deployments. Start a [private gateway](/neuraltrust/deployment/overview#create-a-private-trustgate-gateway), choose **Kubernetes**, and keep the wizard open. Treat the generated `values.yaml` as secret credential and setup input, not authoritative chart values. Choose **Manual** only for custom OpenShift manifests; it displays `CONTROL_PLANE_JWT` and `DATA_AGENT_JWT`.

## Install

The install sequence — namespace, Secrets, values file, `helm upgrade --install`, verification — is the same on every provider and is covered in the [Quick start](/neuraltrust/deployment/quickstart). This page covers only what differs on OpenShift, where the chart renders native Routes instead of Ingress.

Deploy from the current maintained `neuraltrust-platform` chart or manifests. Review and map the wizard-generated credentials and settings into the maintained interfaces before applying; do not run the generated local-chart command unchanged. Move credentials into pre-created Secrets or an approved secret manager.

Configure Routes or ingress, managed PostgreSQL and Redis connectivity, registry access, DNS, and TLS. Link the registry Secret to service accounts that need pull access. See [Configuration](/neuraltrust/deployment/configuration) and [Secrets](/neuraltrust/deployment/secrets).

## DNS and TLS

```bash
oc get route -n neuraltrust
```

Cluster wildcard DNS and certificates may already cover Route hosts. For custom hosts, follow cluster ingress policy. Expose two Routes:

- LLM/proxy Route targeting the proxy Service's named `http` port (Service port `80`, TrustGate container port `8081`)
- MCP Route targeting the MCP Service's named `http` port (Service port `80`, TrustGate container port `8082`)

Return to the wizard, enter the LLM/proxy URL as the bootstrap **Dataplane URL**, and click **Save and Finish**. Then open **Settings → Agent Gateway → General** and set or verify the separate **LLM URL** and **MCP URL**.
