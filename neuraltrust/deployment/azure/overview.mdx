Use AKS for the Hybrid **data plane**. The control plane stays on NeuralTrust SaaS — see [Overview](/neuraltrust/deployment/overview).

## Cluster baseline

Defaults are a comfortable starting point for Hybrid (**3–4** ×
`Standard_D8s_v5`). External usually wants **one extra node**. Right-size later
— see [Cluster sizing](/neuraltrust/deployment/sizing).

```bash
az aks create \
  --resource-group <RESOURCE_GROUP> \
  --name neuraltrust \
  --node-count 3 \
  --node-vm-size Standard_D8s_v5 \
  --enable-oidc-issuer \
  --enable-workload-identity \
  --generate-ssh-keys

az aks get-credentials \
  --resource-group <RESOURCE_GROUP> \
  --name neuraltrust
```

AKS ships no ingress controller by default — install Application Gateway or NGINX before exposing the data plane.

## Azure choices

- **Ingress / TLS:** Application Gateway or NGINX; Key Vault or cert-manager
- **Identity:** Microsoft Entra Workload ID
- **Datastores:** Flexible Server PostgreSQL and Azure Cache for Redis (private endpoints) — [minimum sizes](/neuraltrust/deployment/configuration#managed-stores)
- **Network:** [Network allowlist](/neuraltrust/deployment/network) (config-sync / DataBridge egress + NeuralTrust inbound source IP); also registry, LLM upstreams, your stores

## GPU workers (optional)

Only if you run Firewall on GPU — see [Firewall](/neuraltrust/deployment/firewall#gpu-workers).

## Install

Once the cluster exists, verify it and create the namespace:

```bash
kubectl get nodes
kubectl get storageclass
kubectl create namespace neuraltrust
```

Create the registry pull Secret ([Images](/neuraltrust/deployment/images)) and your private PostgreSQL / Redis instances, then follow the shared install sequence — Secrets, values file, `helm upgrade --install`, verification — which is the same on every provider:

- [Quick start](/neuraltrust/deployment/quickstart) for the commands
- [Hybrid walkthrough](/neuraltrust/deployment/hybrid-walkthrough) for the reasoning behind each step and what to check when it goes wrong
