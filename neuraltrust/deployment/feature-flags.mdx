These are the chart 2.0.5 switches that materially change the rendered topology.

| Value | Default | Effect |
| --- | --- | --- |
| `global.deploymentMode` | `hybrid` | `hybrid` renders customer runtimes; `external` also renders control planes and local analytics. |
| `global.postgresql.deploy` | `true` | Deploy shared PostgreSQL, or use `false` with external connection values. |
| `global.redis.deploy` | `true` | Deploy shared Redis, or use `false` with external connection values. |
| `global.clickstack.enabled` | `true` | Enables chart 2.0.5's combined raw+metadata SaaS OTLP path. `false` disables that entire path, including metadata. |
| `infrastructure.clickhouse.deploy` | `true` | External only: deploy ClickHouse. Set `false` for a managed endpoint. |
| `data-plane-api.dataPlane.enabled` | `true` | Render the compatibility API shim. |
| `agentgateway.mcp.enabled` | `true` | Render AgentGateway MCP runtime. |
| `agentgateway.configSync.enabled` | `false` | Switch AgentGateway data plane from PostgreSQL-backed configuration to authenticated config sync. |
| `trustguard.configSync.enabled` | `false` | Experimental: switch TrustGuard data plane from PostgreSQL-backed configuration to authenticated config sync. The plane split uses placeholder runtime arguments/ports in chart 2.0.5. |
| `firewall.enabled` | `true` | Include the Firewall subchart. |
| `firewall.firewall.enabled` | `true` | Render Firewall gateway and workers. Keep this aligned with `trustguard.firewall.enabled`. |
| `trustguard.firewall.enabled` | `true` | Configure TrustGuard to call Firewall. |
| `alertengine.enabled` | `true` | Render AlertEngine in External mode. |
| `trustlens.enabled` | `false` | Opt-in work in progress; a release image tag is not supplied by default. |
| `watchdog.enabled` | `false` | Enable optional self-monitoring and remediation. |
| `global.autoGenerateSecrets` | `true` | Generate chart-owned secrets when values are empty. |
| `global.preserveExistingSecrets` | `false` | Skip chart secret creation/update; the operator must pre-create the complete contract. |

<Warning>
**Hybrid telemetry compatibility:** intended product behavior exports metadata only and retains raw prompts/responses in customer PostgreSQL, except for authorized DataAgent/DataBridge retrieval. Chart 2.0.5 does not support metadata-only OTLP through values. Either accept its raw+metadata export, set `global.clickstack.enabled: false` to disable all SaaS ClickStack export, or use an approved patched/newer chart that implements metadata-only export.
</Warning>

AgentGateway config sync is optional and off by default. TrustGuard config sync and the External TrustGuard control/data-plane split should be treated as experimental until the exact chart and image runtime contract has been validated.

## Shared infrastructure

Hybrid resolves AgentGateway, TrustGuard, DataAgent, and `data-plane-api` to one PostgreSQL role/database through `postgresql-secrets`. It similarly resolves Redis through `redis-secrets`.

```yaml
global:
  deploymentMode: hybrid
  postgresql:
    deploy: false
    host: postgres.example.com
    port: 5432
    user: neuraltrust
    database: neuraltrust
    sslMode: require
    existingSecret:
      name: hybrid-postgresql
  redis:
    deploy: false
    host: redis.example.com
    port: 6379
    tls: "true"
    existingSecret:
      name: hybrid-redis
```

External mode keeps per-service database overlays because each control plane owns its migrations. Use `values-v2-managed-datastores.yaml.example` as the source, not the Hybrid shared block alone.

## Platform and routing

`global.platform` accepts `aws`, `gcp`, `azure`, `openshift`, or `kubernetes`. `global.domain` supplies generated hostnames. `global.ingress.provider`, `global.ingress.className`, and provider-specific annotations customize exposure. OpenShift defaults to Routes when `global.ingress.provider: openshift`.

`global.storageClass: ""` uses the cluster default. `global.imageRegistry` replaces the default NeuralTrust registry prefix for mirrored images.

## Optional AWS identity authentication

AgentGateway, TrustGuard, DataCore, and AlertEngine expose service-specific PostgreSQL IAM switches; Redis IAM is also available where documented in the chart. These require matching IRSA permissions and provider values. Start with `values-v2-managed-datastores.yaml.example` and render before applying.

See [Configuration](/neuraltrust/deployment/configuration) for complete minimal overlays and [Secrets](/neuraltrust/deployment/secrets) for key ownership.
