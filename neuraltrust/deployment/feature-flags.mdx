These are the current chart switches that materially change the rendered Hybrid topology.

| Value | Default | Effect |
| --- | --- | --- |
| `global.deploymentMode` | `hybrid` | Must be `hybrid`. Renders customer runtime workloads. |
| `global.postgresql.deploy` | `true` | Deploy shared PostgreSQL, or use `false` with external connection values. |
| `global.redis.deploy` | `true` | Deploy shared Redis, or use `false` with external connection values. |
| `global.clickstack.enabled` | `true` | Enable Hybrid metadata export to SaaS ClickStack. |
| `data-plane-api.dataPlane.enabled` | `true` | Render the data-plane API. |
| `agentgateway.mcp.enabled` | `true` | Render TrustGate MCP. `agentgateway` is TrustGate's technical chart identifier. |
| `agentgateway.configSync.enabled` | `false` | Switch the TrustGate data plane from PostgreSQL-backed configuration to authenticated config sync. |
| `trustguard.configSync.enabled` | `false` | Switch the TrustGuard data plane from PostgreSQL-backed configuration to authenticated config sync. |
| `firewall.enabled` | `true` | Include the Firewall subchart. |
| `firewall.firewall.enabled` | `true` | Render Firewall gateway and workers. Keep this aligned with `trustguard.firewall.enabled`. |
| `trustguard.firewall.enabled` | `true` | Configure TrustGuard to call Firewall. |
| `trustlens.enabled` | `false` | Enable TrustLens when a release image tag is supplied. |
| `watchdog.enabled` | `false` | Enable optional self-monitoring and remediation. |
| `global.autoGenerateSecrets` | `true` | Generate chart-owned secrets when values are empty. |
| `global.preserveExistingSecrets` | `false` | Skip chart secret creation/update; the operator must pre-create the complete contract. |

Hybrid exports metadata only and retains raw prompts/responses in customer PostgreSQL, except for authorized DataAgent/DataBridge retrieval. TrustGate and TrustGuard config sync are optional and off by default.

## Shared infrastructure

Hybrid resolves TrustGate, TrustGuard, DataAgent, and the data-plane API to one PostgreSQL role/database through `postgresql-secrets`. It similarly resolves Redis through `redis-secrets`.

```yaml
global:
  deploymentMode: hybrid
  postgresql:
    deploy: false
    host: postgres.example.com
    port: 5432
    user: neuraltrust
    database: neuraltrust
    sslMode: require
    existingSecret:
      name: hybrid-postgresql
  redis:
    deploy: false
    host: redis.example.com
    port: 6379
    tls: "true"
    existingSecret:
      name: hybrid-redis
```

## Platform and routing

`global.platform` accepts `aws`, `gcp`, `azure`, `openshift`, or `kubernetes`. `global.domain` supplies generated hostnames. `global.ingress.provider`, `global.ingress.className`, and provider-specific annotations customize exposure. OpenShift defaults to Routes when `global.ingress.provider: openshift`.

`global.storageClass: ""` uses the cluster default. `global.imageRegistry` replaces the default NeuralTrust registry prefix for mirrored images.

## Optional AWS identity authentication

TrustGate and TrustGuard expose service-specific PostgreSQL IAM switches; Redis IAM is also available where documented in the chart. These require matching IRSA permissions and provider values. Render the managed-store configuration before applying.

See [Configuration](/neuraltrust/deployment/configuration) for complete minimal overlays and [Secrets](/neuraltrust/deployment/secrets) for key ownership.
