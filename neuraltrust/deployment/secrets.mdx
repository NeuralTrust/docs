---
title: Secrets
description: Secret ownership and external-secret requirements for the NeuralTrust Platform chart.
---

The current chart generates missing application secrets by default and preserves values on ordinary Helm upgrades through `lookup`.

```yaml
global:
  autoGenerateSecrets: true
  preserveExistingSecrets: false
```

For GitOps or an external secret manager, pre-create every required Secret and use:

```yaml
global:
  autoGenerateSecrets: false
  preserveExistingSecrets: true
```

`helm template` cannot preserve generated values with `lookup`. Production GitOps installations should therefore use stable, externally managed Secrets.

## Core secret contracts

| Kubernetes Secret | Important keys | Placement |
| --- | --- | --- |
| TrustGate technical Secret: `agentgateway-secrets` | `SERVER_SECRET_KEY`, `STS_SIGNING_KEY`; External also uses `DB_PASSWORD`, `SENSIBLE_PG_DSN` | Hybrid and External |
| `trustguard-secrets` | `ADMIN_JWT_SECRET`, `TRUSTGUARD_TOKEN_SIGNING_SECRET`, `REDIS_EVENTS_SECRET`; External also uses `DB_PASSWORD`, `SENSIBLE_PG_DSN` | Hybrid and External |
| `trustguard-client-credentials` | `CLIENT_ID`, `CLIENT_SECRET` | Both runtimes |
| `postgresql-secrets` | Hybrid shared `DB_*`, `POSTGRES_*`, `DATABASE_URL`, `POSTGRES_PRISMA_URL`, `SENSIBLE_PG_DSN` | Hybrid; control-plane connection contract in External |
| `redis-secrets` | `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD`, `REDIS_USERNAME`, `REDIS_TLS` | Hybrid |
| `data-plane-jwt-secret` | `DATA_PLANE_JWT_SECRET`, `REDIS_URL` | `data-plane-api` |
| `firewall-secrets` | `JWT_SECRET`, optional `HUGGINGFACE_TOKEN` | When Firewall is enabled |
| `dataagent-secrets` or operator Secret | `ENROLMENT_TOKEN`; externally managed DB flow also needs `DATABASE_URL`, `DB_PASSWORD` | Enrolled Hybrid |
| `control-plane-secrets` | `AUTH_SECRET`, `NEXTAUTH_SECRET`, `CONTROL_PLANE_JWT_SECRET`, `TRUSTGATE_JWT_SECRET` | External |
| `datacore-secrets` | `AUTH_JWT_HS256_SECRET`, optional `POSTGRES_PASSWORD` | External |

## Hybrid OTLP token

Hybrid requires a SaaS-issued ClickStack bearer token unless export is intentionally disabled. Prefer a pre-created Secret:

```yaml
global:
  clickstack:
    existingSecret:
      name: clickstack-otlp-token
      key: OTEL_EXPORTER_OTLP_HEADERS
```

The referenced value is the complete OTLP headers value expected by the workloads. Do not commit it.

## DataAgent enrollment

The enrollment token is never auto-generated:

```yaml
dataagent:
  tenantId: "<TENANT_ID>"
  enrolmentTokenExistingSecret:
    name: dataagent-enrolment
    key: ENROLMENT_TOKEN
```

This Helm enrollment is separate from entering an endpoint and JWT in the [console Advanced settings](/platform/advanced).

## Firewall integration

TrustGate calls TrustGuard using `trustguard-client-credentials`. TrustGuard calls the Firewall service using `firewall-secrets/JWT_SECRET`. Keep both chart switches aligned:

```yaml
firewall:
  enabled: true
  firewall:
    enabled: true

trustguard:
  firewall:
    enabled: true
    existingSecret:
      name: firewall-secrets
      key: JWT_SECRET
```

## Registry credentials

The chart references `gcr-secret` by default but does not create registry credentials. Create that Docker registry Secret or configure `global.imagePullSecrets` for your mirror.

Restrict Secret read access, rotate coordinated credentials together, and render against a non-production namespace before rollout. The chart repository's `SECRETS.md` is the exhaustive key-level contract for pre-created External deployments.
