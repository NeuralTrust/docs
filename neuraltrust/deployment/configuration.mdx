## Generated setup

Start in [TrustGate's private gateway wizard](/neuraltrust/deployment/overview#create-a-private-trustgate-gateway). The visible runtime choices are **Docker** and **Manual**.

**Docker** displays a generated Compose command. That command fetches the maintained TrustGate Compose manifest and supplies configuration-sync, DataAgent enrollment, and OTLP settings.

**Manual** displays exactly these generated environment values and does not display a deployment command:

- `CONTROL_PLANE_URL`
- `CONTROL_PLANE_JWT`
- `COLLECTOR_URL`
- `COLLECTOR_JWT`
- `DATA_AGENT_JWT`

Treat these values as secrets except for service URLs. Inject them into your maintained deployment manifests through an approved secret manager; do not commit them.

After deployment, enter its reachable **Dataplane URL** in the wizard. The app stores it as `TeamGateway.endpoint` for this gateway and derives the LLM and MCP connection hosts from it.

## Operator-managed Kubernetes

Kubernetes is not a selectable runtime in the current wizard. Choose **Manual** only to obtain the five environment values above, then inject them as secrets into maintained Kubernetes or OpenShift manifests. The Manual creation path does not generate Kubernetes manifests, values YAML, or a Helm command. After setup, **Settings → Agent Gateway → Deployment** can regenerate `values.yaml` for the gateway.

If your maintained chart uses the following infrastructure values, set `deploymentMode: hybrid` and point it at **your** PostgreSQL and Redis (`deploy: false`). These are operator-managed chart settings, not wizard output.

```yaml
global:
  deploymentMode: hybrid
  platform: kubernetes
  domain: platform.example.com
  postgresql:
    deploy: false
    host: postgres.example.com
    port: 5432
    user: neuraltrust
    database: neuraltrust
    sslMode: require
    existingSecret:
      name: hybrid-postgresql
  redis:
    deploy: false
    host: redis.example.com
    port: 6379
    tls: "true"
    existingSecret:
      name: hybrid-redis
```

Use the maintained manifests' documented Secret interfaces for the Manual values. Do not infer chart keys from the environment-variable names. See [Credential contracts](/neuraltrust/deployment/secrets#credential-contracts) for configuration-sync, OTLP, and DataAgent credentials.

## Managed stores

Do not run PostgreSQL or Redis in the cluster. Pre-create one shared database/role and Redis; Helm does not create managed-service users.

| Store | Minimum size |
| --- | --- |
| **PostgreSQL** | **2 vCPU**, **4 GiB RAM**, **20 GiB** storage |
| **Redis** | **1 GiB** memory |

| Provider | PostgreSQL | Redis |
| --- | --- | --- |
| AWS | RDS/Aurora `db.t4g.medium`, 20 GiB+ | ElastiCache `cache.t4g.small` |
| GCP | Cloud SQL `db-custom-2-4096`, 20 GiB+ | Memorystore **1 GiB** |
| Azure | Flexible Server **2 vCores / 4 GiB**, 20 GiB+ | Cache for Redis **C1** (1 GiB)+ |

Reach both over private networking from the cluster. Secret key contracts: [Secrets](/neuraltrust/deployment/secrets).

## Ingress

```yaml
global:
  platform: aws
  domain: platform.example.com
  storageClass: gp3
  ingress:
    className: alb
    aws:
      certificateArn: arn:aws:acm:region:account:certificate/id
```

`global.domain` controls ingress names rendered by the operator-managed chart only. It does not control the hosts displayed in the console; those derive from the finalized Dataplane URL. Cluster storage is only for optional chart components — not for PostgreSQL or Redis.

Render and install with your maintained deployment manifests. See [Feature flags](/neuraltrust/deployment/feature-flags) and [Secrets](/neuraltrust/deployment/secrets).
