Use the examples shipped with the NeuralTrust Platform chart as canonical inputs:

- `values-required.yaml`: minimal Hybrid contract.
- `values-openshift.yaml`: Hybrid with native OpenShift Routes.
- The concise Hybrid, External, and managed-store examples on this page.

Copy the minimal file before editing:

```bash
cp values-required.yaml values-hybrid.yaml
```

## Minimal Hybrid

```yaml
global:
  deploymentMode: hybrid
  platform: kubernetes
  domain: platform.example.com
  clickstack:
    authToken: "<CLICKSTACK_OTLP_TOKEN>"

dataagent:
  tenantId: ""
  enrolmentToken: ""
```

Hybrid exports metadata over token-authenticated OTLP while raw payloads remain in customer PostgreSQL. Reference the OTLP credential from a Secret in tracked values:

```yaml
global:
  clickstack:
    existingSecret:
      name: clickstack-otlp-token
      key: OTEL_EXPORTER_OTLP_HEADERS
```

DataAgent remains absent until `tenantId` and either `enrolmentToken` or `enrolmentTokenExistingSecret.name` are set.

## Minimal External

```yaml
global:
  deploymentMode: external
  platform: kubernetes
  domain: platform.example.com
  observability:
    hostedExport:
      enabled: false

infrastructure:
  clickhouse:
    deploy: true

alertengine:
  enabled: true

trustlens:
  enabled: false
```

External renders the app/control-plane API, TrustGate and TrustGuard control planes, DataCore, local ClickStack collector, and AlertEngine in addition to runtime workloads.

## Managed stores

In Hybrid, configure `global.postgresql` and `global.redis`; all relevant workloads use the shared secrets.

```yaml
global:
  postgresql:
    deploy: false
    host: postgres.example.com
    port: 5432
    user: neuraltrust
    database: neuraltrust
    sslMode: require
    existingSecret:
      name: hybrid-postgresql
  redis:
    deploy: false
    host: redis.example.com
    port: 6379
    tls: "true"
    existingSecret:
      name: hybrid-redis
```

In External, set `global.postgresql.deploy: false`, `global.redis.deploy: false`, and `infrastructure.clickhouse.deploy: false`, then configure each service endpoint and shared ClickHouse Secret under its service block. Pre-create service databases/roles; Helm does not create users on managed PostgreSQL.

## Ingress and storage

```yaml
global:
  platform: aws
  domain: platform.example.com
  storageClass: gp3
  ingress:
    className: alb
    aws:
      certificateArn: arn:aws:acm:region:account:certificate/id
```

Generated hosts use `global.domain`. Set component ingress hosts only when generated names do not fit your DNS design. Kubernetes ingress is independent of the [web app custom domain](/platform/custom-domain).

## Render before install

```bash
helm template neuraltrust-platform \
  oci://europe-west1-docker.pkg.dev/neuraltrust-app-prod/helm-charts/neuraltrust-platform \
  --namespace neuraltrust \
  -f values-hybrid.yaml
```

The chart validates mode names, Hybrid ClickStack credentials, DataAgent enrollment, and the `data-plane-api` backend. See [Feature flags](/neuraltrust/deployment/feature-flags) and [Secrets](/neuraltrust/deployment/secrets).
