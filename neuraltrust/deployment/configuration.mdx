Use the examples shipped with chart 2.0.5 as canonical inputs:

- `values-required.yaml`: minimal Hybrid contract.
- `values-v2-hybrid.yaml.example`: complete Hybrid and managed-store notes.
- `values-v2-external.yaml.example`: self-hosted control, runtime, and analytics.
- `values-v2-managed-datastores.yaml.example`: External with managed PostgreSQL, Redis, and ClickHouse.
- `values-openshift.yaml`: Hybrid with native OpenShift Routes.

Copy the shipped examples before editing:

```bash
cp values-v2-hybrid.yaml.example values-v2-hybrid.yaml
cp values-v2-external.yaml.example values-v2-external.yaml
cp values-v2-managed-datastores.yaml.example values-v2-managed-datastores.yaml
```

<Warning>
**External TrustGuard compatibility:** chart 2.0.5 renders the External TrustGuard control plane, but its subchart marks the control/data-plane split arguments and ports as placeholders from an in-progress upstream implementation. Do not infer a functional production runtime from successful Helm rendering. Validate startup, health checks, configuration sync, and API behavior against the exact chart and TrustGuard image release before production use.
</Warning>

## Minimal Hybrid

```yaml
global:
  deploymentMode: hybrid
  platform: kubernetes
  domain: platform.example.com
  clickstack:
    authToken: "<CLICKSTACK_OTLP_TOKEN>"

dataagent:
  tenantId: ""
  enrolmentToken: ""
```

Chart 2.0.5 requires the OTLP token by default because its Hybrid path exports raw payloads and metadata together. It cannot configure metadata-only OTLP through values. Choose one of three behaviors: accept chart 2.0.5's raw+metadata export; set `global.clickstack.enabled: false` to disable the entire SaaS ClickStack path, including metadata; or use an approved patched/newer chart that implements metadata-only export. When using token-authenticated OTLP, reference a Secret in tracked values:

```yaml
global:
  clickstack:
    existingSecret:
      name: clickstack-otlp-token
      key: OTEL_EXPORTER_OTLP_HEADERS
```

DataAgent remains absent until `tenantId` and either `enrolmentToken` or `enrolmentTokenExistingSecret.name` are set.

## Minimal External

```yaml
global:
  deploymentMode: external
  platform: kubernetes
  domain: platform.example.com
  observability:
    hostedExport:
      enabled: false

infrastructure:
  clickhouse:
    deploy: true

alertengine:
  enabled: true

trustlens:
  enabled: false
```

External renders the app/control-plane API, AgentGateway and TrustGuard control-plane resources, DataCore, local ClickStack collector, and AlertEngine in addition to runtime workloads. The TrustGuard control-plane runtime remains subject to the compatibility warning above.

## Managed stores

In Hybrid, configure `global.postgresql` and `global.redis`; all relevant workloads use the shared secrets.

```yaml
global:
  postgresql:
    deploy: false
    host: postgres.example.com
    port: 5432
    user: neuraltrust
    database: neuraltrust
    sslMode: require
    existingSecret:
      name: hybrid-postgresql
  redis:
    deploy: false
    host: redis.example.com
    port: 6379
    tls: "true"
    existingSecret:
      name: hybrid-redis
```

In External, set `global.postgresql.deploy: false`, `global.redis.deploy: false`, and `infrastructure.clickhouse.deploy: false`, then configure each service endpoint and shared ClickHouse Secret as shown in `values-v2-managed-datastores.yaml.example`. Pre-create service databases/roles; Helm does not create users on managed PostgreSQL.

## Ingress and storage

```yaml
global:
  platform: aws
  domain: platform.example.com
  storageClass: gp3
  ingress:
    className: alb
    aws:
      certificateArn: arn:aws:acm:region:account:certificate/id
```

Generated hosts use `global.domain`. Set component ingress hosts only when generated names do not fit your DNS design. Kubernetes ingress is independent of the [web app custom domain](/platform/custom-domain).

## Render before install

```bash
helm template neuraltrust-platform \
  oci://europe-west1-docker.pkg.dev/neuraltrust-app-prod/helm-charts/neuraltrust-platform \
  --version 2.0.5 \
  --namespace neuraltrust \
  -f values-v2-hybrid.yaml
```

The chart validates mode names, Hybrid ClickStack credentials, DataAgent enrollment, and the `data-plane-api` backend. See [Feature flags](/neuraltrust/deployment/feature-flags) and [Secrets](/neuraltrust/deployment/secrets).
