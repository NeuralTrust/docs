Open **Platform settings → Advanced**. Owners and admins can edit **Data Plane Configuration**; other roles see a read-only message.

## Connect to existing

Use **Connect to existing** when the Helm deployment already exists.

1. Enter the **Data Plane Endpoint**, including `https://`.
2. Enter the **JWT Secret** used to authenticate control-plane requests.
3. Select **Save** and confirm the change.

Both fields are required before Save is enabled. The endpoint may differ from an already connected TrustGate URL because the control plane uses it for synchronization and analytics.

<Warning>
Treat the JWT as a credential. It must match the deployed data-plane API contract and must not be stored in source control.
</Warning>

This console flow records an endpoint and JWT on the team. It does **not** install Helm resources and it is distinct from DataAgent Helm enrollment, which uses `dataagent.tenantId` and a SaaS-issued `ENROLMENT_TOKEN`.

## Provision from the console

The Advanced page currently provides provisioning flows for:

- **AWS**: account ID, role ARN, region, and chart version.
- **GCP**: project, region, service-account credentials, and chart version.

Provisioning runs asynchronously. The page shows queued/running/succeeded/failed status, refreshes automatically, and provides **Refresh status**. After a successful deployment, the team is linked automatically; owners can later upgrade or destroy the provisioned deployment.

The **Azure** tab is visible, but Azure UI provisioning is marked **coming soon**. Deploy AKS separately and use **Connect to existing**.

<Note>
Console provisioning and the Infrastructure Helm guides are separate installation paths. When platform engineering installs the NeuralTrust Platform chart directly, use the [Hybrid provider guides](/neuraltrust/deployment/overview#provider-guides), then connect the resulting endpoint here.
</Note>

SaaS teams normally do not need this page. Hybrid teams use it to connect a customer-hosted data plane to NeuralTrust SaaS.

See [Deployment models](/neuraltrust/deployment/deployment-models) for model boundaries and [Secrets](/neuraltrust/deployment/secrets) for Helm credentials.
