The OWASP Top 10 for LLM Applications is a risk list, not a control framework — so
this page grades coverage rather than claiming it. Each entry says what the risk is,
which capability meets it, and how far that goes.

<Note>
**Coverage is not a score.** A risk marked *Covered* means a control exists on the
traffic path and can enforce. *Partial* means something is detected but not stopped,
or only one side of the risk is reachable. *Not covered* means these two products do
not address it and something else has to.
</Note>

## At a glance

| | Risk | Coverage |
|---|---|:--|
| **LLM01** | Prompt Injection | Covered |
| **LLM02** | Sensitive Information Disclosure | Covered |
| **LLM03** | Supply Chain | Partial |
| **LLM04** | Data and Model Poisoning | Not covered |
| **LLM05** | Improper Output Handling | Partial |
| **LLM06** | Excessive Agency | Covered |
| **LLM07** | System Prompt Leakage | Partial |
| **LLM08** | Vector and Embedding Weaknesses | Not covered |
| **LLM09** | Misinformation | Partial |
| **LLM10** | Unbounded Consumption | Covered |

## LLM01 — Prompt Injection

*Crafted input that subverts the model's instructions.*

[Prompt Guard](/trustguard/detectors/content-security) detects jailbreaks and
injection from whoever is typing, on input and output.
[Indirect Prompt Injection](/trustguard/detectors/agent-mcp-security) covers the
harder half: hostile instructions in what a tool hands back, and in tool descriptions
themselves. [URL Analyzer and Document Analyzer](/trustguard/detectors/content-security)
extend that to pages an agent is asked to read and files it is given, including scans
via OCR.

Sensitivity is three preset cards — Permissive, Balanced, Strict — not a number you
type.

## LLM02 — Sensitive Information Disclosure

*Secrets, PII or proprietary data leaving through the model.*

[Data Loss Prevention](/trustguard/detectors/data-loss-prevention) detects PII and
secrets — API keys, access tokens, JWTs — on input and output, and is the one detector
that **masks**, which is what makes the Transform action available.
[Regex Replace](/trustgate/policies/regex-replace) handles values you can write down
exactly. Separately, [credential redaction](/trustguard/data-handling#credential-redaction)
keeps credentials out of stored records before anything is written.

## LLM03 — Supply Chain

*Compromised models, plugins or tool servers.*

The [Registry](/trustgate/registry/overview) is the allowlist: a gateway reaches only
the [model providers](/trustgate/registry/models) and [MCP servers](/trustgate/registry/mcp)
registered on it, each an entry plus the credential that reaches it.
[Indirect Prompt Injection](/trustguard/detectors/agent-mcp-security) inspects tool
descriptions, which is where a malicious server does its work.

**Partial.** Registration controls *what may be reached*; it does not assess the
provenance or integrity of the model or server behind the entry. There is no scanning
of an MCP server's code or publisher before you register it.

## LLM04 — Data and Model Poisoning

*Corrupted training or fine-tuning data.*

**Not covered.** Both products sit on the traffic path at inference time and have no
visibility into how a model was trained or fine-tuned.

## LLM05 — Improper Output Handling

*Model output consumed downstream without validation.*

Detectors run on the **Output** side, and [guardrails](/trustgate/policies/guardrails)
can refuse or rewrite a non-streamed response. TrustGuard, Bedrock Guardrail and Model
Armor can rewrite in place; Azure Content Safety never sees the response at all.

**Partial, and this is the limit to read twice.** A streamed response
[cannot be inspected or blocked as it is written](/trustgate/policies/guardrails#the-one-limit-shared-by-all-of-them) —
the words are already reaching the reader by the time a detector would decide. On a
streaming application, output-side inspection observes; it does not protect. It also
does nothing about how *your* downstream code handles what it receives.

## LLM06 — Excessive Agency

*An agent with more capability, permission or autonomy than the task needs.*

[Access levels](/trustgate/access/overview) decide which people reach which servers,
inherited from the gateway default, with anything outside a selection arriving as a
[request rather than a refusal](/trustgate/access/overview#requests-instead-of-refusals).
The [MCP registry](/trustgate/registry/mcp) bounds which tool servers exist at all,
[Tool Injection](/trustgate/policies/tool-injection) controls what is injected into the
tool surface, and the [per-tool rate limiter](/trustgate/policies/per-tool-rate-limiter)
bounds how often any single tool can run. Both always enforce — they offer no observe
mode.

## LLM07 — System Prompt Leakage

*The system prompt extracted through the model.*

Output-side detection can catch a leak in progress:
[Prompt Guard](/trustguard/detectors/content-security) runs on both sides, and
[Regex Replace](/trustgate/policies/regex-replace) will scrub a known marker string.

**Partial.** There is no detector whose purpose is system-prompt disclosure, and the
streaming limit above applies. Adversarial testing for this risk lives in TrustTest
([System prompt disclosure](/trusttest/create/system-prompt-disclosure)), not on the
runtime path.

## LLM08 — Vector and Embedding Weaknesses

*Attacks against RAG stores, embeddings and retrieval.*

**Not covered.** The gateway proxies an [embeddings endpoint](/trustgate/endpoints/embeddings),
but neither product inspects a vector store, its index, or what retrieval returns.
Content retrieved and then passed to a model as part of a prompt is inspected as
prompt content — that is LLM01, not this.

## LLM09 — Misinformation

*Confident, wrong output — including insecure code suggestions.*

[Custom Moderation](/trustguard/detectors/content-security) (Beta) covers subjects you
define yourself, which is the closest available control for keeping a model inside
its intended scope.

**Partial.** Topic scoping is not factuality. Neither product verifies claims, and
there is no groundedness or hallucination check on the runtime path.

## LLM10 — Unbounded Consumption

*Resource exhaustion, runaway cost, denial of wallet.*

[Rate limiter](/trustgate/policies/rate-limiter) with an additional **Throttle** mode
that delays rather than blocks, [LLM budget](/trustgate/policies/llm-budget) for spend,
[request size limiter](/trustgate/policies/request-size-limiter) for payloads, and the
[per-tool rate limiter](/trustgate/policies/per-tool-rate-limiter) for tool calls.
[Routing fallback](/trustgate/llm/routing#fallback) keeps an application alive when a
provider degrades.

## Machine-readable tagging

Findings are **not** tagged with LLM01–LLM10 identifiers in the API or console. This
page is the mapping. TrustTest tags its scenarios with OWASP references, but those are
test-catalog tags, not runtime findings.
