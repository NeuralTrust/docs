title: Custom Domain
description: Configure a custom hostname for the NeuralTrust web application.
---

A custom domain gives users a branded hostname for the NeuralTrust web app, such as `ai.example.com`, instead of the default console URL.

<Note>
This setting affects the browser-facing application hostname. It does not configure Kubernetes Ingress or OpenShift Routes for TrustGate, TrustGuard, APIs, or other chart workloads. Configure those with Helm `global.domain` and ingress values.
</Note>

## Configure a hostname

1. Open **Platform settings → Domains → Custom Domain**.
2. Add the hostname you control.
3. Copy the DNS records shown by the application into your DNS provider.
4. Wait for DNS propagation, then retry verification from the application if needed.

Use the exact target and verification records displayed in the UI; they can vary by environment. Choose a subdomain because many DNS providers do not allow a CNAME at the zone apex.

NeuralTrust provisions TLS after ownership and routing checks succeed. Do not remove the DNS verification record while the domain is active unless the application instructs you to.

## SSO

If your identity provider restricts callback or redirect URLs, add the custom hostname using the callback path shown by your NeuralTrust SSO configuration. Keep the existing NeuralTrust callback until sign-in has been tested.

## Troubleshooting

- Confirm public DNS with `dig CNAME <hostname>` and `dig TXT <verification-name>`.
- Remove conflicting A, AAAA, or CNAME records.
- Allow for the record TTL before retrying verification.
- If DNS verifies but TLS remains pending, confirm the hostname points to the exact target shown in the app.

For runtime hostnames, see [Deployment configuration](/neuraltrust/deployment/configuration). For connecting an existing Hybrid endpoint to the console, see [Advanced](/platform/advanced).
