# Manual User Sync

Manual User Sync allows you to synchronize users from your Microsoft Entra ID groups to NeuralTrust on-demand. You control exactly when synchronization happens.

## When to Use Manual User Sync

Manual User Sync is ideal when you:

- Prefer explicit control over when users are provisioned
- Need to perform initial setup before enabling SCIM
- Manage a small team with infrequent changes
- Want to preview changes before applying them

## How It Differs from SCIM

| Feature | Manual User Sync | SCIM |
|---------|------------------|------|
| **Trigger** | You click "Sync Now" | Automatic |
| **Direction** | Pull from Azure | Push from Azure |
| **Real-time** | No | Yes |
| **Requires Azure Enterprise App** | No | Yes |
| **Best for** | Small teams, occasional changes | Large teams, frequent changes |

<Note>
You can use both Manual User Sync and SCIM together. Manual sync is useful for immediate changes, while SCIM handles ongoing synchronization.
</Note>

## Prerequisites

Before using Manual User Sync, ensure:

- [SSO is configured](/platform/sso) with API permissions enabled
- Azure AD groups created for your team roles
- Owner or Admin role in NeuralTrust

<Warning>
Manual User Sync requires the optional API permissions from the SSO setup (User.Read.All, GroupMember.Read.All, Group.Read.All). If you skipped this step, return to the [SSO configuration](/platform/sso#step-5-add-api-permissions-optional) to add them.
</Warning>

## Part 1: Create Azure AD Groups

### Step 1: Plan Your Group Structure

Create security groups in Azure AD that map to NeuralTrust roles:

| Azure AD Group | NeuralTrust Role | Permissions |
|----------------|------------------|-------------|
| `NeuralTrust-Owners` | Owner | Full administrative access |
| `NeuralTrust-Admins` | Admin | Manage users and settings |
| `NeuralTrust-Members` | Member | Standard user access |

### Step 2: Create Groups in Azure Portal

1. Go to <a href="https://portal.azure.com" target="_blank">Azure Portal</a>
2. Navigate to **Microsoft Entra ID** → **Groups**
3. Click **+ New group**
4. Configure the group:
   - **Group type**: Security
   - **Group name**: `NeuralTrust-Owners` (or your chosen name)
   - **Group description**: Users with Owner role in NeuralTrust
   - **Membership type**: Assigned
5. Click **Create**
6. Repeat for each role group

### Step 3: Add Users to Groups

1. Open the group you created
2. Go to **Members** → **+ Add members**
3. Search for and select users
4. Click **Select**

---

## Part 2: Configure Group Mapping in NeuralTrust

### Step 1: Open User Sync Settings

1. Log in to <a href="https://app.neuraltrust.ai" target="_blank">NeuralTrust</a> as Owner or Admin
2. Go to <a href="https://app.neuraltrust.ai/settings/sso" target="_blank">**Settings** → **SSO** → **User Sync**</a>

### Step 2: Add Group Mappings

1. Click **Group Mapping**
2. For each role, click **+ Add Mapping**
3. Configure the mapping:

| Setting | Value |
|---------|-------|
| **Azure AD Group** | Select your Azure group (e.g., NeuralTrust-Owners) |
| **NeuralTrust Role** | Select the corresponding role (e.g., Owner) |

4. Click **Save**

### Example Configuration

```
Azure Group: NeuralTrust-Owners    →  Role: Owner
Azure Group: NeuralTrust-Admins    →  Role: Admin
Azure Group: NeuralTrust-Members   →  Role: Member
```

## Part 3: Run Synchronization

### Step 1: Preview Changes

Before applying changes, preview what will happen:

1. Go to <a href="https://app.neuraltrust.ai/settings/sso" target="_blank">**Settings** → **SSO** → **User Sync**</a>
2. Click **Preview**
3. Review the pending changes:

| Action | Description |
|--------|-------------|
| **Add** | New users that will be created |
| **Update** | Existing users whose role will change |
| **Remove** | Users that will be deactivated |

### Step 2: Execute Sync

Once you've reviewed the preview:

1. Click **Sync Now**
2. Watch the progress indicator
3. Review the sync results

### Step 3: Verify Users

1. Go to <a href="https://app.neuraltrust.ai/settings/team" target="_blank">**Settings** → **Team**</a>
2. Confirm users appear with correct roles
3. Check that removed users are deactivated

## Role Priority

When a user belongs to multiple Azure AD groups that map to different NeuralTrust roles, they receive the **highest priority role**.

### Priority Order (Highest to Lowest)

1. **Owner** — Full administrative access
2. **Admin** — User and settings management
3. **Member** — Standard access

### Example

If user `jane@company.com` is in both:
- `NeuralTrust-Admins` → Admin
- `NeuralTrust-Members` → Member

Jane will be assigned the **Admin** role (higher priority).

## Sync Behavior

### Adding Users

1. User is added to a mapped Azure AD group
2. You click **Preview** to see pending additions
3. You click **Sync Now** to create accounts
4. Users can immediately sign in via SSO

### Updating Users

1. User's group membership changes in Azure AD
2. You click **Preview** to see pending role changes
3. You click **Sync Now** to apply changes
4. User's role is updated immediately

### Removing Users

1. User is removed from all mapped Azure AD groups
2. You click **Preview** to see pending removals
3. You click **Sync Now** to deactivate accounts
4. User can no longer access NeuralTrust

<Note>
Removed users are deactivated, not deleted. Their data and activity history are preserved for compliance purposes.
</Note>

## Sync Schedule

Manual User Sync does not run automatically. Consider establishing a regular sync schedule:

| Team Size | Recommended Frequency |
|-----------|----------------------|
| Small (< 20 users) | Weekly or as needed |
| Medium (20-100 users) | Daily |
| Large (> 100 users) | Consider using SCIM instead |

<Note>
If your team changes frequently, consider enabling [SCIM Provisioning](/platform/scim) for automatic synchronization.
</Note>

## Audit Trail

All sync operations are recorded in the audit log:

1. Go to <a href="https://app.neuraltrust.ai/settings/audit-logs" target="_blank">**Settings** → **Audit Logs**</a>
2. Filter by Category: **User Management**
3. Look for events like:
   - `user_sync.started`
   - `user_sync.user_created`
   - `user_sync.user_updated`
   - `user_sync.user_deactivated`
   - `user_sync.completed`

## Troubleshooting

| Issue | Cause | Solution |
|-------|-------|----------|
| "Failed to fetch groups" | API permissions not granted | Add User.Read.All, GroupMember.Read.All, Group.Read.All permissions in Azure and grant admin consent |
| Groups not appearing | Permissions not consented | Click "Grant admin consent" in Azure API permissions |
| User not syncing | Not in any mapped group | Add user to a mapped Azure AD group |
| Wrong role assigned | Multiple group membership | Check role priority — user gets highest role |
| "Connection failed" | SSO misconfigured | Verify SSO connection in Settings → SSO |
| Sync takes too long | Large number of users | Consider using SCIM for large organizations |

### Common Errors

**"Insufficient privileges"**
- The Azure app registration needs Application permissions, not Delegated permissions
- Ensure admin consent is granted for all permissions

**"Group not found"**
- The Azure AD group may have been deleted or renamed
- Remove the mapping and create a new one with the correct group

## Best Practices

1. **Use descriptive group names** like `NeuralTrust-Owners` rather than generic names
2. **Preview before syncing** to avoid unexpected changes
3. **Document your group mappings** for team reference
4. **Sync after organizational changes** such as new hires or departures
5. **Review audit logs** after each sync to verify changes

## Comparison: When to Use Each Method

| Scenario | Recommended Method |
|----------|-------------------|
| Initial setup and testing | Manual User Sync |
| Team of < 20 with rare changes | Manual User Sync |
| Team of 20+ with regular changes | SCIM |
| Need immediate control | Manual User Sync |
| Want set-and-forget automation | SCIM |
| Compliance requires explicit approval | Manual User Sync |
