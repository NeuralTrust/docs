TrustTest is a testing framework for AI red teaming and functional evaluation.
Point it at a model, agent, or HTTP endpoint, generate or supply test cases, and
keep the results so you can rerun the same assessment after every change.

## Two kinds of test

<CardGroup cols={2}>
  <Card title="Red teaming" icon="flame" href="/trusttest/create/threat-detection/overview">
    Jailbreaks, prompt injection, data leaks, unsafe outputs, and agent misuse.
  </Card>
  <Card title="Functional evaluation" icon="check-square" href="/trusttest/create/functional/overview">
    Does the system still answer correctly, stay on-topic, and meet your criteria?
  </Card>
</CardGroup>

Red teaming does not replace functional evaluation. Run both against the same
target when you need security evidence and product quality in one plan.

## FAQ

<AccordionGroup>
<Accordion title="When should I rerun an assessment?">
After material changes to the model, system prompt, tools, retrieval data, or
surrounding application. Run them regularly so regressions show up as the
system evolves.
</Accordion>
<Accordion title="Can results stay in my environment?">
Yes. `FileSystemClient` writes JSON locally. `NeuralTrustClient` persists the
same artifacts in the platform. See
[Connect to NeuralTrust](/trusttest/connect/client).
</Accordion>
<Accordion title="What can TrustTest evaluate?">
The Python library supports `HttpTarget` and custom targets. The web UI currently
requires an LLM exposed over REST. Multi-turn probes need a `ConversationTarget`;
`HttpTarget` already provides that.
</Accordion>
</AccordionGroup>
