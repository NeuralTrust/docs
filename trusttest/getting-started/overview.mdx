<p className="nt-lead">
  TrustTest is an AI red-teaming and evaluation toolkit. Point it at a model,
  agent, or HTTP endpoint. Generate or supply test cases, score them, and keep
  the results so you can rerun the same assessment after every change.
</p>

## How it works

<Steps>
<Step title="Connect a target">
[HTTP](/trusttest/connect/http), an [LLM provider](/trusttest/connect/overview),
or a custom target.
</Step>
<Step title="Create tests">
[Built-in probes](/trusttest/create/threat-detection/overview), your datasets,
or a knowledge base.
</Step>
<Step title="Evaluate">
[Heuristics and LLM-as-judge](/trusttest/evaluate-result/overview), with a
strategy you can rerun after each change.
</Step>
</Steps>

## Two kinds of test

<CardGroup cols={2}>
  <Card title="Red teaming" icon="flame" href="/trusttest/create/threat-detection/overview">
    Jailbreaks, prompt injection, data leaks, unsafe outputs, and agent misuse.
  </Card>
  <Card title="Functional evaluation" icon="check-square" href="/trusttest/create/functional/overview">
    Does the system still answer correctly, stay on-topic, and meet your criteria?
  </Card>
</CardGroup>

Red teaming does not replace functional evaluation. Run both against the same
target when you need security evidence and product quality in one plan.

## FAQ

<AccordionGroup>
<Accordion title="When should I rerun an assessment?">
After material changes to the model, system prompt, tools, retrieval data, or
the surrounding application.
</Accordion>
<Accordion title="Can results stay in my environment?">
Yes. `FileSystemClient` writes JSON locally. `NeuralTrustClient` persists the
same artifacts in the platform. See [Connect to NeuralTrust](/trusttest/connect/client).
</Accordion>
<Accordion title="What can TrustTest evaluate?">
The Python package supports `HttpTarget` and custom targets. The web UI currently
requires an LLM exposed over REST. Multi-turn probes need a `ConversationTarget`;
`HttpTarget` already provides that.
</Accordion>
</AccordionGroup>
