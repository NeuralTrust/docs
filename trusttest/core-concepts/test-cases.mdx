## Test Cases & Probes

This document outlines the architecture and details for evaluating and testing large language models (LLMs) through predefined objectives, test cases, and interactions. It also also includes the capability to dynamically generate questions based on a knowledge base to enhance the evaluation process.

## Key Components

### 1. **Interaction**

An `Interaction` represents a single interaction between the LLM and the user. It includes the question posed to the LLM, the response generated by the LLM, and the context (which is optional).

### 2. **TestCase**

A `TestCase` consists of a list of `Interaction` objects, along with a context that applies to the entire test case. Each test case can be uniquely identified via an ID.

### 3. **TestSet**

A `TestSet` is a collection of `TestCase` objects. This serves as the container for all the test cases needed to evaluate the LLM on various tasks. The test set can be serialized to or deserialized from a dictionary format.

### 4. **Objective**

An `Objective` defines a test goal. It includes an initial question (prompt) for the LLM and descriptions of what constitutes a true or false response. This is crucial for assessing the accuracy of the LLM’s responses.

### 5. **Probe**

A `Probe` is the base class for any test that evaluates the model against predefined test cases or objectives. Probes fetch or generate these test cases, which can then be evaluated using the LLM.

### 6. **ComplianceDatasetProbe**

This is a specialized probe that focuses on evaluating a model's compliance with various predefined objectives. These objectives can relate to categories like **data leakage**, **toxicity**, **SQL injection**, etc. The `ComplianceDatasetProbe` can pull objectives from YAML files, allowing for flexible and dynamic testing.

### 7. **DatasetProbe**

A `DatasetProbe` is designed to read questions and expected responses from a dataset. The dataset can be stored in formats like JSON or Parquet. This probe generates test cases by fetching model responses for each question in the dataset and compares the response to the expected one.

### 8. **RAGProbe**

The `RAGProbe` generates test cases by creating questions from documents stored in a knowledge base. It distributes questions across different topics proportionally to the number of documents in each topic, using various question generation strategies.

#### Features of the `RAGProbe`:
- **Knowledge Base Integration**: Generates questions based on documents stored in a knowledge base.
- **Topic Distribution**: Distributes questions across topics based on the number of documents available.
- **Question Generation**: Uses a variety of question types (e.g., simple, complex, hypothetical) to generate a diverse set of test cases.
- **Customization**: Users can specify the number of questions, the description of the agent generating questions, and the question types to use.

#### Workflow for `RAGProbe`:
1. **Initialize Knowledge Base**: Loads the knowledge base containing documents and topics.
2. **Generate Questions**: Distributes questions across topics and generates them using multiple strategies, such as simple factual questions or complex, hypothetical questions.
3. **Create Test Cases**: For each question, a `TestCase` object is generated that includes the generated question, expected response, and context.
4. **Model Evaluation**: Model responses are generated for each question, and the responses are evaluated against expected answers. 

    - **Question Generation**: The system utilizes an LLM to dynamically generate questions from the knowledge base. This allows for test cases to be continuously updated and varied according to the available content in the knowledge base.
    - **Context-Aware Questioning**: The LLM considers the context of the document or topic to generate relevant and meaningful questions, ensuring the evaluation is based on accurate understanding.

### 9. **Probe Categories**

- **Data Leak**
- **Off-Policy**
- **Off-Tone**
- **Off-Topic**
- **System Configuration Leak**
- **Toxicity**
- **SQL Injection**

These categories represent different evaluation criteria for model behavior, such as ethical considerations, security concerns, and task-specific performance.

## Workflow

1. **Objective Selection**: Probes like the `ComplianceDatasetProbe`, `DatasetProbe`, and `RAGProbe` load objectives or questions from external files or knowledge bases. These objectives define the test cases that the model will be evaluated against.

2. **Test Case Generation**: Probes generate `TestCase` objects, each consisting of multiple `Interaction` objects (questions and responses). For `RAGProbe`, this process involves generating questions from a knowledge base and ensuring a diverse set of test cases is created.

3. **Response Generation**: The LLM is queried with the questions from the test cases. Its responses are then captured and evaluated based on predefined criteria (e.g., truth descriptions).

4. **Evaluation**: The responses are compared to the true descriptions (from the objectives). Test cases are classified as either successful (true) or failed (false) based on the accuracy and appropriateness of the model's responses.

5. **Question Modification**: The `RAGProbe` allows for dynamic modification of the generated questions by applying context-based adjustments. This ensures that questions reflect not only the document’s content but also adhere to specific testing needs.

## Dataset Formats

Probes can interact with datasets in various formats:

- **JSON**: A simple, widely-used format that stores questions and expected responses.
- **Parquet**: A columnar storage format that allows for efficient reading and writing of large datasets. The dataset must contain the required fields: `question` and `context`.

## Refreshing Responses

In cases where the model’s responses need to be updated (e.g., after a model update or a change in objective), the system allows for refreshing the responses by running the test cases again.

## Conclusion

The Probe Framework provides a flexible and extensible approach to testing large language models across various tasks. It supports compliance checks, dataset-based evaluation, and category-specific tests, ensuring that models can be rigorously evaluated before deployment. The ability to dynamically generate questions from a knowledge base ensures that the test cases remain relevant and up-to-date, improving the thoroughness and accuracy of model evaluation.
