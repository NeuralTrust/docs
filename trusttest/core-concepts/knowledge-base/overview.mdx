This module provides connector classes for integrating with different systems to **read documents**, **predict topics**, and **associate documents with those topics**. It supports both dynamic topic discovery and the use of a **predefined list of user-specified topics**.

At its core, all connectors implement a shared `KnowledgeBase` interface, ensuring consistent behavior regardless of backend. This includes capabilities for **document storage**, **topic management**, **retrieval**, and **similarity-based querying**.


There are three main classes provided:

- `AzureKnowledgeBase`
- `Neo4jKnowledgeBase`
- `InMemoryKnowledgeBase`

Each class provides a consistent interface for **managing**, **retrieving**, and **classifying structured knowledge**, while utilizing different backends to suit various needs.


## Core Interface: `KnowledgeBase`

The abstract base class `KnowledgeBase` defines the required methods and properties any connector must implement:

### Topic Management

- `initialize_topics()` / `async_initialize_topics()`: Initializes topic labels, either synchronously or asynchronously, typically through embedding-based clustering or LLM-based summarization.
- `topics`: Returns a list of all discovered or assigned topics in the knowledge base.
- `filter_by_topic(topic: str)`: Filters documents to only include those under a specific topic.

### Document Access

- `documents`: Returns all documents stored in the knowledge base.
- `documents_per_topic`: Groups and returns documents by their assigned topic.
- `choose_document()`: Selects and returns a single document—can be used for sampling or testing.


### Similarity & Search

- `get_neighbors()`: Retrieves documents similar to a given seed document using vector similarity.



## Connectors

### AzureKnowledgeBase

Leverages **Azure Cognitive Search** and is best suited for:

- Cloud-based document indexing and storage
- Full-text search with advanced filtering and ranking
- Integration with Microsoft’s AI-powered search stack



### Neo4jKnowledgeBase

Built on **Neo4j**, this connector excels at:

- Handling complex document relationships
- Graph-based querying and clustering
- Constructing dynamic knowledge graphs



### InMemoryKnowledgeBase

A minimal, no-dependency implementation designed for:

- Prototyping and local testing
- Lightweight, quick-start environments
- Small-scale document classification


## Shared Features

All connectors support:

- **LLM-based topic discovery** to automatically detect meaningful clusters of documents.
- **Embedding-based similarity search** for semantic retrieval and neighborhood expansion.
- **Manual topic overrides** to allow controlled classification using predefined topic lists.
- **Document sampling and filtering** based on topic or similarity.

These capabilities make the framework adaptable across a wide range of use cases—from enterprise knowledge systems to local ML experimentation.

## Topic Creation Process

The topic creation pipeline groups unlabeled documents into coherent topics using embeddings, dimensionality reduction, clustering, and LLM-based summarization. This process is triggered when no predefined (seed) topics are provided.

---

### Workflow Steps

1. **Document Retrieval**
   - Pulls all documents from Azure Cognitive Search using the mapped `id` and `content` fields.
   - Filters out empty or whitespace-only content.

2. **Embedding Generation**
   - Applies an embedding model to each document’s content (truncated to `3 * max_tokens`).
   - Produces high-dimensional semantic vectors for clustering.

3. **Dimensionality Reduction**
   - Uses **UMAP** to reduce embedding vectors to a lower-dimensional space for clustering.
   - Parameters such as `n_neighbors`, `n_components`, and initialization strategy are tuned based on document count.

4. **Topic Clustering**
   - Runs **HDBSCAN** over the reduced vectors to group documents into topic clusters.
   - Noise and outliers are discarded (`label = -1`).

5. **LLM-based Topic Naming**
   - For each valid topic cluster, generates a name using a language model.
   - Uses up to `max_docs` samples per topic and truncates each sample to `max_doc_length`.

6. **Return Structure**
   - Returns:
     - A dictionary mapping topic names to associated documents.
     - A flat list of all topic names.
     - A flat list of all processed documents.

### Function Signature

```python
async def _load_docs_without_seed_topic(
    max_doc_count: Optional[int] = None,
    max_tokens: int = 8192
) -> Tuple[Dict[str, List[Document]], List[str], List[Document]]:
```

---

### Arguments

#### `max_doc_count: Optional[int]`
- Limits the number of documents retrieved from the search backend.
- If `None`, fetches all available documents.

#### `max_tokens: int = 8192`
- Controls the amount of content used per document during embedding and topic naming.
- Helps fit within model context windows when summarizing.

#### Internal Argument Notes:
- `content_field` and `id_field` are resolved from `self._fields_mapping`, used to extract text and IDs from search results.
- UMAP and HDBSCAN settings are dynamically adjusted based on the number of documents to ensure quality results.

---

### Topic Naming Helper

```python
async def _get_topic_name(
    topic_documents: List[Document],
    max_docs: int = 10,
    max_doc_length: int = 500,
    max_tokens: int = 8192
) -> str:
```

#### `max_docs: int = 10`
- Number of documents sampled per topic to generate the label.

#### `max_doc_length: int = 500`
- Character limit per document snippet included in the prompt.

#### `max_tokens: int = 8192`
- Overall token budget for the LLM input prompt, including all sampled documents.

## Summary

The knowledge base connectors in this module abstract the complexity of storage and retrieval while offering advanced features like:

- Topic initialization and LLM-based naming
- Embedding clustering with support for similarity search
- Unified API via the `KnowledgeBase` interface
- Multiple backend choices to suit any scale or system

Whether you're building a smart search engine, an automated research assistant, or an interactive knowledge explorer, these connectors give you a consistent, extensible foundation.
