The `AzureKnowledgeBase` and `Neo4jKnowledgeBase` connectors leverage **Large Language Models (LLMs)** and **embedding-based approaches** to enhance document management, classification, retrieval, and topic discovery. These techniques are vital in automating the analysis and organization of large document sets, improving the efficiency of knowledge base systems.

### LLM-based Topic Summarization

When predefined topics are not available, the system dynamically generates topics by analyzing document content. This process is powered by **LLM-based summarization**, which identifies the most relevant topic names from clusters of related documents.

The core idea is to cluster documents based on content similarity and then use a **large language model** (LLM) to summarize and extract meaningful, concise topic names from those clusters.

#### How LLM-based Topic Summarization Works:
1. **Document Selection**: A set of documents related to a specific topic is selected, either through keyword searches or dynamic clustering methods.
2. **Content Concatenation**: The content from these selected documents is concatenated and truncated to fit within the model's token limit, ensuring that only the most important information is passed to the LLM.
3. **LLM Summarization**: The concatenated content is fed into an LLM, which processes the text and generates a meaningful topic label. This label is designed to capture the essence of the documents in a human-readable format.

LLM-based topic summarization is particularly useful when the documents are not explicitly tagged or categorized and when there’s a need to derive topics from large datasets dynamically.

#### Key Benefits:
- **Dynamic Topic Creation**: Generates topics on-the-fly without requiring predefined tags or labels.
- **Contextual Understanding**: The LLM can capture nuances and relationships between terms and phrases, providing richer topic names.
- **Scalability**: This approach scales well for large document sets, where manual categorization or predefined topic lists may be insufficient.

### Embedding-based Document Classification

In addition to LLM-based summarization, **embedding models** are used to represent documents as vectors in a high-dimensional space. Each document is transformed into an embedding (a vector), which can be used for various tasks such as similarity search, clustering, and classification.

The `embedding-based document classification` method is based on the idea that semantically similar documents are closer in the vector space, making it easy to group, retrieve, and classify them.

#### How Embedding-based Document Classification Works:
1. **Embedding Generation**: Each document's content is transformed into an embedding using an embedding model, such as a transformer-based model (e.g., BERT, RoBERTa).
2. **Dimensionality Reduction with UMAP**: Since embeddings are often high-dimensional, **UMAP (Uniform Manifold Approximation and Projection)** is used to reduce the dimensionality of the embeddings while preserving the relationships between documents.
3. **Clustering with HDBSCAN**: After reducing the dimensionality, **HDBSCAN (Hierarchical Density-Based Spatial Clustering of Applications with Noise)** is used to perform clustering on the embeddings. This clustering algorithm groups similar documents together based on their proximity in the reduced embedding space.

#### Key Benefits:
- **Efficient Clustering**: The combination of embeddings, UMAP, and HDBSCAN enables efficient clustering of large document sets, making it easy to identify related documents and topics.
- **Semantic Similarity**: Embedding-based approaches capture semantic meaning, allowing for more accurate document groupings compared to traditional keyword-based methods.
- **Scalability**: Embeddings can handle large datasets efficiently, enabling real-time document classification and retrieval even for vast knowledge bases.

Embedding-based classification is particularly useful for handling **unstructured data** or when documents need to be clustered based on underlying semantic relationships rather than predefined labels.

### Finding Similar Documents with Embeddings

Once documents are clustered, they can be further analyzed for **similarity**. The `get_neighbors` method retrieves documents that are most similar to a given "seed" document, based on their content embeddings.

This similarity search allows the system to find relevant documents that share similar content, even if they don’t contain the same keywords. The embeddings represent the content in a **continuous vector space**, where documents with similar meanings are placed closer together, even if they use different terminology.

#### How Similarity Search Works:
1. **Document Embedding**: Each document in the knowledge base is represented as an embedding.
2. **Seed Document**: A "seed" document is chosen, and its embedding is used to search for similar documents.
3. **Neighbor Search**: The system uses cosine similarity (or another distance metric) to identify documents that are closest in the vector space to the seed document.
4. **Similarity Ranking**: The retrieved documents are ranked by similarity, and the most relevant ones are returned.

#### Key Benefits:
- **Context-Aware Similarity**: Unlike traditional keyword search, embedding-based similarity takes the entire context of the document into account, ensuring that semantically similar documents are found.
- **Scalable Retrieval**: Embedding-based search can handle a large number of documents efficiently, even with millions of documents in the knowledge base.
- **Improved Relevance**: Because the system is searching based on content meaning rather than exact keywords, it can surface more relevant results.

This method is essential when a **user needs to find documents with similar themes or concepts**, even if they don't share the same exact wording.

# Client Class

The `Client` class serves as an abstract base class that defines the structure and common interface for different client implementations. Below, you'll find a detailed overview of two specific implementations: `FileSystemClient` and `NeuralTrustClient`.

## FileSystemClient

The `FileSystemClient` is a client implementation that interacts with the file system to save and load TrustTest entities locally. This is particularly useful when you want to store data on the local machine or in a specified directory rather than a remote server.

### Key Features:
- **Local Storage**: Saves TrustTest entities such as evaluators, evaluation scenarios, evaluation runs, and test sets in local directories.
- **Directory Structure**: The client organizes data into different subdirectories based on the type of entity being saved (e.g., `custom_evaluators`, `testsets`, etc.).

### Constructor
The constructor of the `FileSystemClient` class takes an optional `path` argument that defines the local storage directory.

- `path`: The path where the local storage directory is created (default is `trusttest_db`).

### Methods

#### `save_custom_evaluator`
- **Description**: Saves a custom evaluator to the local file system in the `custom_evaluators` directory.

#### `get_custom_evaluator`
- **Description**: Loads a custom evaluator from the local storage by its name.

#### `save_evaluation_scenario`
- **Description**: Saves an evaluation scenario to local storage in a directory named after the scenario's ID.

#### `get_evaluation_scenario`
- **Description**: Loads an evaluation scenario from the local storage by its ID.

#### `save_evaluation_scenario_run`
- **Description**: Saves an evaluation scenario run to local storage.

#### `get_evaluation_scenario_run`
- **Description**: Loads an evaluation scenario run from local storage.

#### `save_evaluation_scenario_test_set`
- **Description**: Saves a test set to local storage under the respective evaluation scenario directory.

#### `get_evaluation_scenario_test_set`
- **Description**: Loads the most recent test set from the local storage for a given evaluation scenario.

## NeuralTrustClient

The `NeuralTrustClient` is a client implementation that interacts with the Neural Trust API, allowing you to save and load TrustTest entities to and from the cloud. This implementation is useful for remote storage and integration with the Neural Trust system.

### Key Features:
- **Neural Trust API Integration**: Allows saving and loading of TrustTest entities via HTTP requests to the Neural Trust API.
- **Authentication**: Requires an authentication token to interact with the API.
- **Error Handling**: Custom error handling for API responses, with different exceptions raised for specific error conditions.

### Constructor
The constructor of the `NeuralTrustClient` class requires an authentication token (`token`), a base URL (`base_url`), and a timeout duration (`timeout`).

- `token`: The authentication token for the Neural Trust API.
- `base_url`: The base URL of the Neural Trust API (optional, defaults to `BASE_URL`).
- `timeout`: The timeout duration for the API requests (optional, defaults to 10 seconds).

### Methods

#### `save_evaluation_scenario`
- **Description**: Sends a POST request to the Neural Trust API to save an evaluation scenario.

#### `get_evaluation_scenario`
- **Description**: Sends a GET request to the Neural Trust API to retrieve an evaluation scenario by its ID.

#### `save_evaluation_scenario_run`
- **Description**: Sends a POST request to the Neural Trust API to save an evaluation scenario run.

#### `get_evaluation_scenario_run`
- **Description**: Sends a GET request to the Neural Trust API to retrieve an evaluation scenario run by its ID.

#### `save_evaluation_scenario_test_set`
- **Description**: Sends a POST request to the Neural Trust API to save a test set for an evaluation scenario.

#### `upsert_evaluation_scenario_test_set`
- **Description**: Sends a PUT request to the Neural Trust API to either insert a new test set or update an existing one.

#### `get_evaluation_scenario_test_set`
- **Description**: Sends a GET request to the Neural Trust API to retrieve a test set for a given evaluation scenario.

#### `save_evaluator`
- **Description**: Sends a POST request to the Neural Trust API to save an evaluator.

#### `get_evaluator`
- **Description**: Sends a GET request to the Neural Trust API to retrieve an evaluator by its name.

## Error Handling

Both `FileSystemClient` and `NeuralTrustClient` may raise exceptions in certain situations:

- **FileSystemClient**:
  - `ValueError`: Raised when a requested resource (e.g., evaluator, test set) is not found in the local storage.

- **NeuralTrustClient**:
  - `NeuralTrustApiError`: Raised when there is an error while communicating with the Neural Trust API. The error may be related to authentication issues, missing resources, or server errors.
  - The `NeuralTrustApiError` contains detailed information, including the status code and the URL of the failed request.

## How to Use and Configure the Clients

### Using `FileSystemClient`

The `FileSystemClient` is ideal for local development and testing when you need to store and load TrustTest entities on your local machine. To use the `FileSystemClient`, follow these steps:

1. **Install Dependencies**: Ensure you have the required dependencies installed, especially for the `EvaluationScenario`, `TestSet`, and `CustomEvaluator` objects.

2. **Instantiate the Client**:

    ```python
    from trusttest.clients import FileSystemClient

    # Initialize the FileSystemClient with the desired storage directory
    client = FileSystemClient(path="path/to/storage")
    ```

3. **Save Entities**: Use the `save_*` methods to save your TrustTest entities.

    ```python
    # Save a custom evaluator
    client.save_custom_evaluator(custom_evaluator)

    # Save an evaluation scenario
    client.save_evaluation_scenario(evaluation_scenario)
    ```

4. **Load Entities**: Use the `get_*` methods to load entities from the local storage.

    ```python
    # Load a custom evaluator by its name
    evaluator = client.get_custom_evaluator("evaluator_name")

    # Load an evaluation scenario by its ID
    scenario = client.get_evaluation_scenario("scenario_id")
    ```

### Using `NeuralTrustClient`

The `NeuralTrustClient` allows you to interact with the Neural Trust API for cloud-based storage of your TrustTest entities. To use the `NeuralTrustClient`, follow these steps:

1. **Install Dependencies**: Ensure you have the required dependencies installed, especially for the `EvaluationScenario`, `TestSet`, and `Evaluator` objects.

2. **Obtain the API Token**: You need an API token to authenticate with the Neural Trust service. Contact the Neural Trust support team to obtain your token.

3. **Instantiate the Client**:

    ```python
    from trusttest.clients import NeuralTrustClient

    # Initialize the NeuralTrustClient with your API token
    client = NeuralTrustClient(token="your_api_token")
    ```

4. **Save Entities**: Use the `save_*` methods to send your TrustTest entities to the Neural Trust API.

    ```python
    # Save an evaluation scenario
    client.save_evaluation_scenario(evaluation_scenario)

    # Save a test set
    client.save_evaluation_scenario_test_set("scenario_id", test_set)
    ```

5. **Load Entities**: Use the `get_*` methods to retrieve entities from the Neural Trust API.

    ```python
    # Load an evaluation scenario by its ID
    scenario = client.get_evaluation_scenario("scenario_id")

    # Load a test set by its evaluation scenario ID
    test_set = client.get_evaluation_scenario_test_set("scenario_id")
    ```

### Summary

The `FileSystemClient` is ideal for local use, offering a simple and efficient way to store and load TrustTest entities directly from the file system. On the other hand, the `NeuralTrustClient` integrates with the Neural Trust API, allowing you to store and retrieve entities from the cloud, making it perfect for production environments or large-scale evaluations. Both clients provide a flexible and consistent interface, making it easy to switch between local and cloud storage depending on your needs.

In addition to these flexible client options, by combining **LLM-based topic summarization** with **embedding models**, the system enables advanced capabilities for **document classification**, **topic discovery**, and **similarity search**. These approaches unlock powerful features for knowledge base management, allowing users to:

- Dynamically generate **topics** from document clusters without the need for predefined labels.
- Use **semantic embeddings** for **efficient document retrieval** and classification.
- Identify **similar documents** through advanced similarity search, even when they don’t share explicit keywords.

Whether building a knowledge base for a large organization or organizing an extensive document repository, these techniques equip you with the tools necessary to make documents easier to navigate and classify.
